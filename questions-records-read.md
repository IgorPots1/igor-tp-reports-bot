# Точка 3 — путь чтения рекордов (ветка feature/club-records-read-path)

## Проблема (найдена фактом)
74 strava_best_effort + 38 official_protocol в `club_records` были невидимы: вкладка читала только
снапшоты (реконструкция) + `loadCoachRecords` (`source=coach_confirmed`). Остальные source не читались
ничем. materialize их не спасал (он «Does NOT touch club_records», кладёт только реконструкцию).

## Решение
`club_records` УНИКАЛЕН по (student_id, distance_key) → одна строка на пару, `source` задаёт слот:
- **coach_confirmed → «Гонка»**, перекрывает всю дистанцию (hidden прячет) — поведение НЕ менял.
- **official_protocol → «Гонка»** (реальный результат протокола), бьёт реконструированную гонку.
- **strava_best_effort → «Лучший отрезок тренировки»** (измеренный сегмент, НЕ гонка), бьёт реконструкцию.

Иерархия в слоте: гонка = coach > official > race_events(снапшот); отрезок = strava > реконструкция.
Разделение «Гонки / Лучшие отрезки» сохранено: strava НИКОГДА не попадает в гонки/топы.

Клубные топы (только гонки): coach(verified) + official + race_events(снапшот). strava исключён.
Топы теперь идут по всем видимым ученикам (а не только по тем, у кого есть снапшот) — иначе ученик
с official-гонкой, но без реконструкции, не попал бы в топ.

## Перф (Игорь просил проверить)
НЕ добавлял round-trip: расширил ТОТ ЖЕ запрос coach на `in (coach, official, strava)`.
Head-to-head замер: старый `eq coach_confirmed` (29 строк) = **112 мс**, новый `in` (141 строка) = **116 мс** → **+4 мс**.
Полный getClubRecords 395↔640 мс — это разброс на чтении снапшотов/students (не трогал), не от правки.

## Проверено фактом (до/после)
- Alena Grill (все strava): каждая дистанция = гонка(race_events) + отрезок(strava). В топах только 42k гонка, strava нет.
- Сергеева: 10k → official как гонка (49:00) + reconstructed отрезок; 21k → coach; 5k → strava отрезок. Разделение цело.
