# Ученик видит свой план на входе (ветка feature/club-next-workout)

## Решения (Игорь подтвердил)
1. **Объём:** только БЛИЖАЙШАЯ тренировка (сегодня/завтра) — одна карточка.
2. **Описание:** ЦЕЛИКОМ; при пустом (13 из 270) — фолбэк на структуру интервалов.
3. **Выходной:** план показываем С ПОМЕТКОЙ «выходной», не прячем.

## Факт (проверено до реализации)
- В кэше по планам есть: название, длительность (мин), дистанция (у большинства нет — по времени/пульсу),
  структура (блоки + метрика percentOfThresholdHr/Pace), описание. Тип — классификатором (бег/вел).
- Тренерских пометок в описаниях НЕ найдено (скан 270: [скобки]=0, {фигурные}=0, тренер/coach/RPE=0,
  порог%=0). Описания ученические. Потому решение «описание целиком» безопасно.
- Выходных в календаре мало (6, у 3), коллизий с планом сейчас 0 — но механизм заложен.

## Реализация
- `getClubNextWorkout(studentId)` (service.ts): ближайший плановый из workout_cache (is_planned, date>=today,
  order workout_date/order_on_day), классификатор типа, длительность/дистанция, описание (full, иначе null),
  `steps` = структура-фолбэк (repetition → «N × (…)»), `isDayOff` (club_calendar_entries kind=day_off на дату).
- Route `POST /api/m/club/next-workout` (gated CLUB_PLAN_ENABLED, read-only).
- UI: карточка ПЕРВОЙ на вкладке Profile (дефолтная вкладка входа), рамка-акцент, «выходной»-бейдж,
  описание целиком (whitespace pre-wrap) либо список шагов.
- Флаг **CLUB_PLAN_ENABLED** (по умолчанию OFF, как все клубные фичи — слепой rollout).

## Проверено фактом
Реальные ученики: Романовский «Бег по пульсу» сегодня 50 мин; Трофимова «6 х 6 мин» завтра 66 мин
(описание + структура «Разминка 10 мин · … · 6 × (Работа 6 мин + Отдых 2 мин) · Заминка 5 мин»);
Богачев «4 х 10 мин» сегодня. Пустые описания → структура-фолбэк. tsc/eslint/build/smoke-club/initdata зелёные.

Открыто: структура-фолбэк иногда метит разминку как «Работа» (у кого intensityClass не warmUp) — не
критично, фолбэк только для пустых описаний; можно уточнить эвристику ролей, если попросишь.
