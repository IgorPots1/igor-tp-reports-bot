# Run Club импорт — ЭТАП 3: план (описание, НЕ реализация)

Опирается на ЭТАП 1 (`docs/runclub-people-match.md`, 41 уверенно сопоставленный) и ЭТАП 2
(`docs/runclub-import-sources.md`). Реализацию не начинать до явной команды.

## 1. Иерархия источников рекордов (согласована)

При конфликте на одну `(ученик, дистанция)` побеждает более высокий:

```
coach_confirmed  >  official_protocol  >  race_events  >  strava_best_effort  >  реконструкция
```

- **strava_best_effort** (НОВЫЙ источник) — честный отрезок из GPS-потока Strava. Ниже `race_events`
  (гонка — соревновательный результат, надёжнее), выше реконструкции (наш best-window по лапам —
  приблизительный). `source='strava_best_effort'`, `trust='verified'` (измеренный отрезок, не расчёт).
- **Правило записи:** strava_best_effort попадает в `club_records` ТОЛЬКО если на `(ученик, дистанция)`
  нет ничего выше рангом, либо существующее — реконструкция и Strava быстрее. `coach_confirmed` /
  `official_protocol` / `race_events` НЕ перебиваются (в оценке — 35 защищённых, они не трогаются).

## 3. Дедупликация

- **Рекорды:** ключ `(student_id, distance_key)` — один лучший на дистанцию; импорт сверяет с
  существующим по иерархии §1, upsert только если Strava выигрывает.
- **Журнал:** у Strava нет `protocol_url`. Ключ для strava-записей — `(student_id, strava_best_effort_id)`
  (`strava_best_effort_id` — bigint-строкой, глобально уникален). Это же даёт идемпотентность.
- **Треки:** ключ — по TP-записи (см. §5) либо по `external_id` Strava.
- **Люди:** импорт ТОЛЬКО по уверенно сопоставленным (exact + подтверждённые подсказки из ЭТАПа 1).
  Пустые/неоднозначные профили (два Olga, три пустые Яны, тест-акки) НЕ импортируются.

## 4. Идемпотентность

- Все upsert — по стабильным ключам (`strava_best_effort_id`, Strava `external_id`) → повторный прогон
  не плодит дублей.
- `source='strava_best_effort'` на каждой записи → импортированное отличимо и откатываемо.
- **Транспорт-фильтр (темп < 2:30/км) ПЕРЕД записью** — 43 «рекордных» отрезка/мусор не переезжают
  (иначе марафон 1:50:13 и полумарафон 12:08 заедут вместе с данными, README §5.1).
- Маппинг людей берётся из зафиксированного отчёта ЭТАПа 1 (не пересчитывается на каждом прогоне) →
  импорт детерминирован.

## 5. Треки: решение по схеме (по проверке 1053 старых Strava-пробежек)

Вопрос: класть полилинию на существующую TP-запись (ключ прежний, схему не менять) или нужен второй
источник? Проверка — совпадают ли те же пробежки с `trainingpeaks_workout_cache` по
`(ученик, дата, дистанция ±2%, время ±60с)`.

> **ПРОВЕРЕНО ФАКТОМ (997/1053 = 94.7%).** Из 1053 старых Strava-пробежек (с полилинией, >60д) у 41
> сопоставленного **997 (94.7%) нашли пару в `trainingpeaks_workout_cache`** по дате+дистанции ±2%+
> время ±60с; по дате+дистанции — 999/1053 (94.9%). Без пары в кэше на ту дату — только **42 (4%)**,
> ещё 12 — дистанция мимо. **Блокер МНИМЫЙ, гипотеза подтвердилась:** люди льют одни и те же пробежки
> и в Strava, и в TP. → **Ветка «схему не меняем» (ниже).**

- **✓ ВЫБРАНО (большинство нашло пару, 94.7%):** полилиния Strava ложится на СУЩЕСТВУЮЩУЮ
  `trainingpeaks_workout_tracks` запись той же TP-тренировки. **Схему НЕ меняем, ключ `workout_cache_id`
  прежний.** Поток на фазу треков: для каждой Strava-пробежки найти парную TP-запись в
  `trainingpeaks_workout_cache` (тот же матч дата+дистанция±2%+время±60с → её `workout_cache_id`) →
  декод Strava-полилинии (обратный к `encodePolyline`) → обрезка 300 м (`cropTrackForPrivacy`) →
  Douglas-Peucker → записать `polyline` в `trainingpeaks_workout_tracks` по этому `workout_cache_id`
  там, где трека ещё нет (у нас треки только за 60 дней → почти все старые пустые).
- **Не потребовалось (второй источник):** реальных дыр всего **42 (4%)** — Strava-пробежки без TP-пары.
  Их полилиниям в текущей схеме места нет; на первом заходе просто ПРОПУСКАЕМ (4% потери истории треков
  не стоят новой таблицы). Если позже захочется и их — тогда `external_source='strava'`+`external_id`
  либо `strava_tracks`, отдельным решением.

## 6. Порядок импорта (фазы, когда дойдёт до реализации)

1. Зафиксировать маппинг people (ЭТАП 1) в data-файл → детерминированный вход.
2. **Аватары** (+31) — дёшево, заметно, риска ноль.
3. **best_efforts → club_records + журнал** (транспорт-фильтр, иерархия §1, идемпотентность §4).
4. **Треки** — по решению §5.

Каждая фаза — отдельный dry-run → ревью → commit. В прод ничего без явной команды.
