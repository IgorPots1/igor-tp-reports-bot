## 2026-06-21 — Стратегия метрик: каденс вручную, достоверность, гейт негодного видео

### Угол колена — конвенция flexion
**Решение:** замер приведён к сгибанию от прямой (0° = прямая нога): `180 − angleDeg(hip,knee,ankle)`. Пороги в reference-ranges.ts уже были в flexion-конвенции.

**Почему:** замер давал внутренний угол (прямая = 180°), а порог «20–35°» — в flexion. Сравнение шло в разных единицах → нормальная нога флагалась красным. Теперь обе величины в одной шкале.

### Каденс — ручной ввод с часов, не из видео
**Решение:** `cadence_spm` убран из видео-замера. В форме — опциональное поле «каденс с часов». Заполнено → показываем в отчёте как контекст «с часов»; пусто → не показываем. LLM трактует каденс только если он введён вручную, и не как измерение из видео.

**Почему:** надёжный каденс из видео требует точного межкадрового счёта и устойчивости к движению камеры; к тому же каденс пейс-зависим и индивидуален. Замер по одной ноге давал ~½ значения и ломался на панораме. Часы дают точное значение без этих рисков.

### Вертикальные колебания — оставлены, но замер переписан
**Решение:** оставляем метрику, но (а) амплитуда считается ПО ЦИКЛАМ (медиана peak-to-trough между соседними контактами), а не глобальный max−min по клипу; (б) перед замером убирается линейный снос hip.y (детренд); (в) знаменатель роста калибруется (shoulder−ankle ≈ 0.75 полного роста, `SHOULDER_ANKLE_HEIGHT_FRACTION`), иначе % раздут; (г) добавлена качественная полоса low/medium/high (`classifyVerticalOscillationBand`). В отчёте — и полоса, и %; при низкой достоверности полоса основная, % — ориентир.

**Почему:** глобальный max−min ловил движение камеры/трансляцию, а заниженный знаменатель раздувал проценты (180% на реальном видео). Требует статичной камеры — это вынесено в требования к съёмке.

### Достоверность per-метрика + гейт негодного видео
**Решение:** каждая измеряемая метрика возвращает `{ value, confidence, reason }`, confidence ∈ ok|low|unavailable; reason — машинный код (`few_contact_cycles`, `low_landmark_visibility`, `camera_motion`, `subject_too_small`), UI маппит в человеческий текст. Пороги — `CONFIDENCE_CONFIG` в reference-ranges.ts (с TODO). Сигналы: число чистых контактов, visibility нужных landmark'ов, движение камеры (снос hip.y / амплитуда цикла), размер объекта. unavailable-метрики в payload к LLM уходят как «не определено» (не числа). Общий гейт: если доступных метрик меньше `minAvailableMetricsForReport` — показываем экран «ролик не подходит» с чек-листом пересъёмки, без частичного отчёта.

**Почему:** на мусорном/непригодном видео нельзя показывать уверенные числа и нельзя давать LLM выдумывать выводы. Явная достоверность отделяет надёжное от шумного, а гейт отсекает заведомо негодные ролики.

### Требования к съёмке — статичная камера
**Решение:** в UI требование: камера неподвижна (телефон на опоре, бегун пробегает мимо), строго сбоку, человек крупно, несколько шагов; убрано «20–30 сек / дорожка»; подчёркнуто «не вести камерой за бегуном».

**Почему:** корректность вертикальных колебаний и детекта контактов напрямую зависит от неподвижности камеры.

## 2026-06-20 — Фаза 1: экранный отчёт в админке

### Инструмент — AdminOS, не публичный self-serve

**Решение:** страница за admin-авторизацией, никакого публичного роута.

**Почему:** исходный план предполагал self-serve (чужой человек сам грузит видео, получает отчёт через ChatPlace). Переосмыслили: ручной режим (Игорь грузит сам) — выше конверсия (личный контакт), проще реализация (нет webhook'ов, нет оплаты внутри тула), безопаснее (данные клиента не гуляют публично). Один и тот же инструмент работает для существующих клиентов и для платного мини-магнита.

---

### Без `@anthropic-ai/sdk`, raw fetch

**Решение:** вызов Anthropic через raw fetch, как в `src/features/nutrition/nutrition-ai-provider.ts`.

**Почему:** SDK 0.105.0 тянет `zod ^3.25 || ^4` как peer dependency — репо zod не использует принципиально. Паттерн raw fetch уже работает в nutrition. SDK не добавляет ничего, что нельзя получить прямым запросом к API.

---

### Без `output_config.format` / `json_schema`

**Решение:** JSON-вывод через промпт («ответь только валидным JSON») + `extractJsonOnly()` + defensive parse.

**Почему:** `output_config.format` с `type: "json_schema"` — beta-фича SDK (требует `anthropic-beta: structured-outputs-2025-12-15`). Beta нестабильна, лишняя зависимость. Промпт + `extractJsonOnly` + defensive parse — проверенный паттерн из nutrition, работает надёжно.

---

### thinking выключен в Фазе 1, параметр заложен

**Решение:** `THINKING_ENABLED = process.env.RUN_ANALYSIS_THINKING_ENABLED === "true"` (дефолт — false). Если включён, тело запроса получает `thinking: { type: "adaptive" }`.

**Почему:** для лид-магнитного анализатора скорость и стоимость важнее глубины рассуждений. Включить позже — одна env-переменная. Форма `{ type: "adaptive" }` верна: это рекомендуемый SDK-вариант (форма `{ type: "enabled", budget_tokens: N }` помечена deprecated).

---

### Дефолт `claude-opus-4-8`, переключение через env

**Решение:** `RUN_ANALYSIS_CLAUDE_MODEL` (дефолт `claude-opus-4-8`), `RUN_ANALYSIS_OPENAI_MODEL` (дефолт `gpt-5.5`), `RUN_ANALYSIS_LLM_PROVIDER` (`claude` | `openai`, дефолт `claude`).

**Почему:** нужно А/Б тестирование opus vs sonnet на реальных видео перед финальным выбором. Переключение без правок кода. `claude-opus-4-8` — самая способная модель для нюансированного тренерского нарратива.

---

### Изоляция от nutrition-модуля

**Решение:** LLM-паттерн скопирован (не импортирован) из nutrition. Единственный общий импорт — `@/lib/admin-auth` (общая инфраструктура, не фича).

**Почему:** нулевая связанность. Если nutrition-модуль рефакторится, run-analysis не ломается. Небольшое дублирование паттерна — сознательная цена.

---

### Admin-cookie авторизация в API route

**Решение:** `/api/run-analysis` проверяет cookie `tp_admin_access` через `hasValidAdminAccessCookie` из `@/lib/admin-auth`. Байпас авторизации допускается **только** при `NODE_ENV === "development"` (локальный хелпер `isLocalDevBypass`). На Vercel — и в preview, и в проде, где `NODE_ENV === "production"` — валидная admin-кука обязательна **всегда**, независимо от наличия `ADMIN_ACCESS_TOKEN`.

**Почему:** вызов идёт из браузера (same-origin), cookie отправляется автоматически. Bearer-токен (как в `send-nutrition-button/route.ts`) не нужен — нет внешних вызовов. Строгий `NODE_ENV === "development"` (вместо более широкого `!== "production"` + отсутствие токена) гарантирует, что роут невозможно открыть без куки на любом задеплоенном окружении.

---

### PDF — клиентски, из кадров в браузере (Фаза 2)

**Решение:** PDF собираем на клиенте из `heroFrameDataUrl` (уже в памяти браузера), не гоняем кадры на сервер.

**Почему:** видео принципиально не должно покидать браузер. Hero frame уже есть как blob-dataURL. Серверный PDF потребовал бы хранение видео/кадров — лишние движущиеся части.

**Статус:** не реализовано. Начать после проверки экранного отчёта на реальных видео.
