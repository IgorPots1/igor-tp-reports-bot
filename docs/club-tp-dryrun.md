# Club → TrainingPeaks: DRY-RUN (Фаза 11)

Что БЫ создалось в TP при исполнении накопленных ОДОБРЕННЫХ записей календаря. Ничего не
исполнено, не поставлено в очередь, статусы не изменены, в TP не записано. Флаг
`CLUB_TP_EXECUTION_ENABLED` — ВЫКЛ. Реальное исполнение — рука Игоря после просмотра этого отчёта.

**Принцип:** в TP создаются ТОЛЬКО НОВЫЕ пометки-тренировки (описательные), существующие
планы/тренировки НЕ трогаются. TP-клиент умеет создавать только workout (события/заметки —
непроверенный API, см. docs/club-phase11-report.md §1), поэтому каждая пометка — это
описательная запланированная тренировка с узнаваемым заголовком, сосуществующая с планом дня.

## Итог
- Одобренных записей (не применённых): 0; спланировано create_workout: 0
- Конфликтов (day_off на дне с планом — не трогаем, ручной просмотр): 0

## Записи (club_calendar_entries, approved, ещё не применённые)

`id=` - это club_calendar_entries.id для команды `scripts/club-execute-one.ts <id> --apply`.

_нет одобренных записей (календарь ещё не наполнен / миграция не применена)_

## Примеры форм по каждому типу (синтетические)

- [план] id=example-day_off · [Клуб] Выходной · клубная пометка → 2026-08-15 -> create_workout title="[Клуб] Выходной · клубная пометка" · unresolved: workoutTypeValueId=7 (Day off) - создание типа Day off проверить ОДНОЙ записью перед массовым исполнением
- [план] id=example-preference · [Клуб] Пожелание: интервальная · клубная пометка → 2026-08-15 -> create_workout title="[Клуб] Пожелание: интервальная · клубная пометка"
- [план] id=example-note · [Клуб] Заметка · клубная пометка → 2026-08-15 -> create_workout title="[Клуб] Заметка · клубная пометка"
- [план] id=example-race · Сочи Полумарафон → 2026-08-15 -> create_workout title="Сочи Полумарафон" · unresolved: targetTime не в поле (CLUB_RACE_SET_PLANNED_TIME=false до capability probe) - целевое время в описании

## Что увидит ученик в своём календаре TP
- Стиль заголовка пометки: text (константа CLUB_MARKER_TITLE_STYLE в tp-execution.ts; "text" = префикс [Клуб], "emoji" = 🛌/🎯/📝/🏁).
- day_off → РОДНОЙ тип TP «Day off» (value_id=7, подтверждён фактом), «[Клуб] Выходной · клубная пометка», is_planned=false. Включи CLUB_DAYOFF_AS_AVAILABILITY=true для Availability.
- preference (тип занятия) → тип Other(100), «[Клуб] Пожелание: … · клубная пометка». Включи CLUB_NOTES_AS_NOTE=true для Note.
- note (свободная) → тип Other(100), «[Клуб] Заметка · клубная пометка». Включи CLUB_NOTES_AS_NOTE=true, чтобы создавать как родную заметку.
- race → запланированный бег (Run) с названием и дистанцией; цель в описании. Включи CLUB_RACE_AS_EVENT=true, чтобы создавать как Event.

## Идемпотентность и отмена
- После успеха id созданной тренировки пишется в club_calendar_entries.applied_tp_workout_id;
  планировщик пропускает применённые записи → повторный прогон не плодит дубли.
- Отмена = удалить созданную тренировку по этому id (существующий delete_workout) и очистить колонку.

## Исполнение (когда флаг ВКЛ) — существующий пайплайн, не тронут
createTrainingPeaksAction(create_workout, pending_coach) → dry-run → подтверждение тренером
→ execute_pending → локальный раннер → executeByType(create_workout) → verify(readback) → откат при провале.
