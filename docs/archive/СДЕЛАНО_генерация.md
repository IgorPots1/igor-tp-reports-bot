## 2. Что конкретно стоит в коде (по 4 задачам)

### Задача 3 — факты для модели
`buildNutritionDailyFactsForNarrative` — `draft-generator.ts:398`. В каждый per-day объект кладёт:
- `items_notable` (еда по секциям + флаги вклада в жир/углеводы; имена, без граммов),
- `day_role` (`rest|pre_long|key|hard|steady`),
- `fat_displaced_carbs` (из finding `high_fat_may_displace_carbs_on_load_day`),
- `fat_policy`,
- `target` (canonical target дня: `carbsGMin/carbsGMax/kcalMin/proteinGMin`) — строится в `methodology.ts buildCanonicalTarget:829`.

### Задача 1 — архитектура derived-прозы
- Тип `NutritionAiNarrative.day_prose: Record<string,string>` — `draft-generator.ts:685`.
- Парс модели → `sanitizeNutritionDayProse`; мёрж в `persistedDailyAnalysis[*].athlete_prose` после получения нарратива.
- Render: `getDailyFactsLines` — `combined-message.ts:450`. Для каждого дня: факт-строка (код) + `resolveUsableNutritionDayProse(item.athlete_prose, facts)` (`combined-message.ts:252`) ИЛИ детерминированный `composeNutritionDayComment` (`combined-message.ts:545`).
- `normalizeStoredDailyFactItem` — `combined-message.ts:144` — теперь протаскивает `athlete_prose` и `target`.

### Задача 2 — промпт
- `systemPrompt` строится в `generateNutritionWeeklyReviewNarrative` — `draft-generator.ts:788` (строки day_prose с `:848`).
- Few-shot/стиль: `NUTRITION_VOICE_STYLE_SPEC_LINES`, `NUTRITION_VOICE_FEWSHOT_EXAMPLES`, `buildNutritionVoiceFewShotBlock` — `narrative-guardrails.ts`.
- Phase 1 добавил в промпт: трёхтактная подача, ЧИСЛА только из `actual`+`target`, carb-loading перед ключевыми, называние еды по `fat_policy`.

### Задача 4 — валидатор
`validateNutritionDayProse` — `telegram-renderer.ts:445`. Две проверки:
- `number_not_in_facts` (`:464`) — каждое число прозы ∈ allow-set (`buildAllowedNutritionProseNumbers:402`: actual + округления, `target` + округления 5/10/25/50, недобор).
- `status_softened` (`:479`) — жёсткий день (`NUTRITION_HARD_DAY_STATUSES:377` + `NUTRITION_HARD_DAY_FINDINGS`) обязан иметь маркер недобора (`NUTRITION_UNDERSHOOT_MARKERS:395`).
Отдельно `validateTelegramReadyNutritionMessage` — `telegram-renderer.ts:486` (тире/markdown/мед-термины/`red_easy_row:530` и т.д.) — на финальном тексте.

## 3. Что РЕАЛЬНО отработало end-to-end, а что только написано

### Подтверждено на живых данных (Khadizhat, прогоны 14.06 вечер)
- GPT-5-совместимость (`ab660b0`): после неё `generation_mode: ai`, `ai_model: gpt-5.2-chat-latest` — **подтверждено** (прогоны 22:03, 22:34→ai-вызов).
- `response_format: json_object` (`91697ca`): парс прошёл (нет `ai_parse_failed`) — **подтверждено**.
- Предохранитель пустых легаси-полей (`e5f251d`): после него `generation_mode=ai` достигнут — **подтверждено**.
- Генерация `day_prose` моделью: проза существовала, называла еду (оладьи/пюре/Belvita) — **подтверждено** (диагностика 22:03).
- Классификация интервалов (`df04e14`): среда показалась как «ключевая темповая», тренировку видит — **подтверждено**.
- Диагностики (`1b2c201`) и ноты `ai_generation_fallback:*` — **подтверждено** (выводы скриптов реальны).
- Срабатывание `status_softened` — **подтверждено** (реальные срезы 4/7 и 3/7 с реальными макросами).

### Написано + юнит-тесты, но НЕ отработало end-to-end на живых данных
- **Phase 1 целиком (`72c6cf7`)** — цели-как-факты, fat-policy `normal`, эталон-промпт: **ни разу не отрендерилось на живых данных.** Каждая перегенерация после деплоя падала в fallback (`ai_http_429` на 22:34). Юнит-тесты есть, живого результата нет.
- Фиксы валидатора (`5017060`, `779fd6e`) — покрыты тестами; **живой ре-прогон после них упёрся в 429**, поэтому финальное поведение валидатора на живых данных после этих коммитов не переподтверждено.
- План-фикс (`24055e1`) — не подтверждён вживую (в показанном обзоре мини-таблица была из старого обзора).
- Ретрай 429/5xx (`fa29eba`) — **локальный, не запушен/не задеплоен.**
- Влияние few-shot эталонов на вывод — не верифицировано (большинство живых прогонов упали в fallback).

**Итог честно:** надёжно работает только цепочка «вызов gpt-5.2 → JSON → проза по дням» в моменты, когда OpenAI не отдаёт 429. Phase 1 (главное, ради чего делалось) на живых данных не наблюдался ни разу.

## 4. Все точки fallback на детерминированный путь

### A. Уровень всего обзора (`generation_mode: "fallback"`)
1. **AI пропущен**: `forceNeedsReview = !hasMethodologyFacts` — `draft-generator.ts:1078`. `hasMethodologyFacts` (`:1072`) требует: `resolvedMacroDays>0`, `dataQuality.parsedDays>0`, `hasResolvedDates`, непустой `one_focus`, `hasUsableTrainingContext` (`tpPastWeek.workouts>0` и cache `ok`/`stale`). Иначе модель не вызывается, ставится fallback-нарратив (билдеры `:738/:773/:629`).
2. **AI вернул null** (внутри `generateNutritionWeeklyReviewNarrative`), каждая ветка пишет `note(...)` и `return null`:
   - `ai_no_api_key` — `:814`
   - `ai_http_<status>` — `:957` (после ретраев `:935`)
   - `ai_empty_content` — `:966`
   - `ai_parse_failed` — `:973`
   - `ai_empty_required_fields` — `:1004` (срабатывает только если `day_prose` тоже пуст; иначе салвэйдж `:1001` оставляет `ai`)
   - `ai_exception` — `:1027`
   - При null причина уходит в `internal_summary.notes` как `ai_generation_fallback:<reason>` — `:1167`.

### B. Уровень отдельного дня (проза → детерминированный комментарий)
3. `resolveUsableNutritionDayProse` — `combined-message.ts:252` возвращает `null` (→ день берёт `composeNutritionDayComment:545`), если: прозы нет / markdown / внутренние термины / `validateNutritionDayProse` дал error (`number_not_in_facts` или `status_softened`). Сообщение не падает — конкретный день выходит «сухим».
4. Дни без макро-данных всегда идут детерминированно (не используют прозу).

### C. Уровень рендера
5. `getDailyFactsLines` пуст (нет canonical `daily_analysis` в неделе обзора) → строка-заглушка в `buildDerivedNutritionCombinedMessage` — `combined-message.ts:1011/1020`.

### Где это всплывает в UI
`page-consistency.ts:253` → `review_fallback_mode` → баннер «Обзор создан в шаблонном режиме» при `generation_mode==="fallback"`.
