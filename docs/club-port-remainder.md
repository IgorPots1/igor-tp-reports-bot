## 3. A3 — TP-пики как источник training_split (флаг ВЫКЛ), лапы фолбэком

`meanMaxSpeedsByDistance` (device mean-max) как источник отрезка, лап-эвристика фолбэком.
Флаг `CLUB_RECORDS_TP_PEAKS` (ВЫКЛ). Код: `loadTpPeaksBest` + `tpPeakPlausible` +
интеграция в `buildTrainingSnapshotRow` (TP-пик предпочтён, если правдоподобен, осмыслен по
A1 и не медленнее лап-отрезка). Инертен: `club_tp_peaks` в проде ПУСТА (0 строк), флаг ВЫКЛ.
Фильтр A1 применяется и к TP-пикам.

**Покрытие на полных данных — знаменатель.** По наряду ожидался 123, ФАКТ — **112 видимых
учеников** (верю данным, не наряду; 53 было на 5% срезе). По дистанциям — ученики с завершённой
пробежкой ≥ дистанции (потенциальный знаменатель на пик): 5k=101, 10k=93, 21k=65, 42k=34.

**Сравнение «время по лапам / по TP / дельта» — требует запуска на Mac.** Скрипт
`scripts/tp-peaks-coverage.ts` перенесён, но он делает **live TP GET** (`getWorkoutDetailsRecord`)
— в песочнице сессии TP нет. Числитель покрытия (у скольких реально есть TP-пик) и дельта
считаются ТОЛЬКО прогоном `npm run tp-peaks-coverage` на твоём Mac с активной TP-сессией
(только GET, ничего не пишет). Пока club_tp_peaks пуста, A3 не влияет на вкладку.
