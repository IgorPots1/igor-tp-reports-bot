# Сверка результатов клуба с протоколами забегов — ПЛАН (Фаза 10.3)

Только план. Реализацию НЕ делать. Цель: подтягивать официальные результаты забегов из внешних
протоколов и апгрейдить клубный рекорд `reconstructed → official_protocol`, но так, чтобы НИКОГДА
не приписать человеку чужой финиш.

## Модель доверия (уже есть в коде)
Клубные рекорды несут `source: reconstructed | coach_confirmed | official_protocol | race_events` и
`trust: verified | preliminary | hidden` (`src/features/club/records.ts`, `types.ts`). Апгрейд из
протокола = поднять source до `official_protocol` (высшая достоверность) + сохранить ссылку и дату сверки.

## Источники (по убыванию приоритета)

### 1. probeg.org (ПРИОРИТЕТ)
- **Как искать:** каталог забегов РФ/СНГ + протоколы. У атлета есть страница со всеми финишами
  (probeg_user_id). Поиск: по фамилии+имени в протоколе конкретного забега, либо по странице атлета.
- **API/страницы:** публичного стабильного API нет — HTML-страницы протоколов (таблица финишей).
  Нужен парсер таблицы (место, имя, время, категория, город/клуб). Уважать нагрузку (задержки, кэш).
- **Поля протокола:** ФИО, чистое/грязное время, место (абс./в группе), возрастная группа, город/клуб,
  иногда bib. probeg_user_id — стабильный идентификатор атлета между забегами (ключевая ценность).
- **Ограничения:** написание ФИО расходится (латиница/кириллица, сокращения); не все забеги в базе;
  время бывает только «грязное» (gun) без чистого (chip).

### 2. Russia Running
- **Как искать:** организатор+таймингер многих РФ-стартов. Результаты по забегу и по участнику.
- **API/страницы:** есть страницы результатов на события; API преимущественно закрытый/частичный —
  практически HTML/JSON-эндпоинты страниц. Идентификатор участника внутри платформы (rr athlete id).
- **Поля:** ФИО, чистое+грязное время, сплиты (на крупных), место, группа, bib, город/клуб.
- **Ограничения:** покрывает свои события; для чужих таймингеров данных нет.

### 3. Беговое сообщество (Московский марафон и др.)
- **Как искать:** организатор крупных московских стартов; результаты на своих страницах событий.
- **API/страницы:** страницы результатов события; API нет/непубличный. Свой athlete id.
- **Поля:** ФИО, чистое время, место, группа, bib.
- **Ограничения:** только свои события; узкий, но качественный сегмент (крупные официальные старты).

Общий вывод: у всех трёх — **страницы, не API**; нужен аккуратный парсер на каждый источник + вежливый
режим (кэш, задержки, никаких массовых запросов). Приоритет отражает покрытие+качество для аудитории клуба.

## Алгоритм сопоставления — три уровня уверенности

Вход: ученик (ФИО из `trainingpeaks_students.student_name`, пол/возраст если есть) + заявленный или
предполагаемый забег (дата, дистанция, город) + его тренировка того же дня из кэша (дистанция+время).

- **ТОЧНЫЙ.** Имя И фамилия ученика найдены в протоколе КОНКРЕТНОГО забега (нормализация: транслит,
  регистр, ё/е, сокращения; допускается 1 опечатка/расхождение окончания). → высокая уверенность.
  **Только ТОЧНЫЙ может привязываться сам** (авто-апгрейд рекорда).
- **ВЕРОЯТНЫЙ.** Фамилии нет в протоколе ИЛИ написание сильно расходится → искать по СОВПАДЕНИЮ
  РЕЗУЛЬТАТА: финиш в протоколе ≈ тренировка ученика в тот же день (дистанция в пределах band, время в
  пределах допуска) на том же забеге/городе. Совпало — КАНДИДАТ. **ВЕРОЯТНЫЙ НЕ привязывается сам** —
  обязательно идёт тренеру на подтверждение в админку с показом ОБЕИХ сторон (что в протоколе: ФИО,
  время, место; что в тренировке: дата, дистанция, время из кэша). Иначе легко приписать чужой финиш.
- **НЕТ.** Ни точного ФИО, ни совпадения результата → ничего не привязываем.

## Хранение идентификаторов атлета (чтобы не искать заново)
Таблица-план `club_athlete_external_ids` (миграция позже): `student_id, platform (probeg|russiarunning|
bceo), external_athlete_id, display_name_on_platform, linked_by (coach|exact_match), linked_at`.
Уникальность `(student_id, platform)`. После первой ТОЧНОЙ привязки/подтверждения ВЕРОЯТНОГО — пишем id,
дальше тянем результаты этого атлета напрямую по id, без повторного фаззи-поиска.

## Апгрейд рекорда (подтверждённого)
`official_protocol`: обновить `club_records` (или снапшот) для дистанции — source=official_protocol,
trust=verified, `protocol_url`, `protocol_verified_at`. Официальный результат бьёт reconstructed
(best-split) как источник высшей достоверности. Coach_confirmed остаётся ручным оверрайдом тренера.

## Порядок реализации (когда дойдут руки — отдельные наряды)
1. Парсер+нормализация ФИО (транслит/кириллица) — общий модуль.
2. По одному источнику за раз, начиная с probeg.org: парсер протокола + страницы атлета.
3. Матчер (три уровня) + очередь ВЕРОЯТНЫХ в админку (обе стороны, кнопки подтвердить/отклонить).
4. Таблица external_ids + апгрейд рекорда + ссылка/дата.
5. Расширение на Russia Running и Беговое сообщество тем же интерфейсом матчера.

Безопасность: авто-привязка ТОЛЬКО ТОЧНАЯ; всё сомнительное — тренеру. Никаких массовых запросов к
источникам; кэш и вежливые задержки. Ничего не пишется в TP из этой сверки.
