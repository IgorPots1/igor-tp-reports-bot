# TP Peak Performances — разведка (read-only, GET)

Дата: 2026-07-25. Наряд B#2. Только чтение через существующий `tp-api-client` (GET, ничего не писалось). Скрипт: `scripts/tp-peaks-probe.ts`. Прощупано на реальной тренировке (athlete 5905779, workout 3865839948, бег 10 км, 2026-07-25).

## Что доступно

**Да, TP считает пиковый темп по дистанциям — но не там, где «деталь тренировки», а в отдельном details-ответе.**

| Источник | Что внутри |
|---|---|
| `getWorkoutDetail` (`/fitness/v6/athletes/{id}/workouts/{id}`) | сводка тренировки. **Пиков НЕТ.** Есть только `personalRecordCount` (число PR в тренировке, не сами значения). |
| `getWorkoutDetailsRecord` (details-запись) | **есть пики:** `meanMaxSpeedsByDistance`, `meanMaxSpeeds`, `meanMaxHeartRates`, `meanMaxPowers`, `meanMaxCadences`, а также `timeInSpeedZones`. |
| `source_snapshot` в нашем кэше | пиков НЕТ (0 peak-ключей) — сканер сохраняет сводку, не details. |
| Кандидатные `/…/peaks` эндпоинты (5 вариантов путей) | все **404** — отдельного «peaks by athlete» по этим путям нет. |

## Формат `meanMaxSpeedsByDistance` (это и есть «пики по дистанциям»)

```
{ "meanMaxes": [
    { "label": "MM400Meter",   "value": 3.61 },   // м/с
    { "label": "MM800Meter",   "value": 3.46 },
    { "label": "MM1Kilometer", "value": 3.42 },
    { "label": "MM1600Meter",  "value": 3.37 },
    { "label": "MM1Mile",      "value": 3.37 },
    { "label": "MM5Kilometer", "value": 3.30 },
    { "label": "MM5Mile",      "value": 3.29 },
    { "label": "MM10Kilometer","value": 3.30 },
    { "label": "MM15Kilometer","value": null },    // null = запись короче дистанции
    ... (MM10Mile, полумарафон, марафон — null для 10к записи)
] }
```
- **Значения — скорость в м/с.** Темп сек/км = `1000 / value`. Пример: MM5Kilometer 3.30 м/с → **5:03/км**; MM10Kilometer 3.296 → 5:03/км.
- Метки покрывают наши целевые дистанции: **MM5Kilometer, MM10Kilometer**, есть MM1Mile/MM5Mile; для 21.1/42.2 — соответствующие метки (HalfMarathon/Marathon) появляются, если запись достаточно длинная, иначе `null`.
- `meanMaxSpeeds` — то же по ВРЕМЕНИ (MM12Seconds, MM1Minute, MM6Minutes, MM12Minutes, MM30Minutes, MM1Hour…), значения тоже м/с.

## Ответы на вопросы наряда

- **Есть ли пики в детали тренировки:** да, в details-записи (`getWorkoutDetailsRecord`), поле `meanMaxSpeedsByDistance`. По distance и по времени.
- **Отдельный эндпоинт истории пиков по атлету:** по прощупанным путям — 404. Per-workout пики есть; агрегированной «Peak Performances history» по этим путям не нашлось (веб-UI, вероятно, собирает из details по многим тренировкам или использует иной путь — надо снять сетевой трейс с web, вне этого наряда).
- **Видны ли тренеру:** да. Probe шёл на тренерской авторизации против тренировки подопечного (5905779) и вернул данные.
- **Премиальность / доступность у всех:** у этого атлета пики есть. TP mean-max — премиальная функция, поэтому у части учеников поле может вернуться пустым/null. Проверено на ОДНОМ атлете; перед реализацией прогнать по всем и посчитать покрытие.

## Вывод для рекордов

TP `meanMaxSpeedsByDistance` — **точнее и чище моего лап-эвристика best-split**: device-computed, без проблемы «паузы внутри лапа», ровно по целевым дистанциям. Но он даёт лучший темп ВНУТРИ тренировки — это по-прежнему НЕ гонка. Для нашей 10к пик 5:03/км = тот же лёгкий темп. То есть переход на TP-пики улучшит ТОЧНОСТЬ реконструкции, но **не решает корневую проблему** (`docs/records-root-cause.md`): настоящих забегов в кэше нет. Разделение race/training_split и якорь E-Predictor всё равно требуют реальных гонок.

## Рекомендация (не реализовано — разведка)
1. Заменить лап-эвристику на TP `meanMaxSpeedsByDistance` как источник «лучшего отрезка» (точнее, снимает pause_gap-шум). Тянуть из details при ingest, класть в `derived_metrics`/новую таблицу.
2. Прогнать покрытие по всем ученикам (у кого пики пустые — премиум недоступен).
3. Race-статус всё равно только через: синк реального забега в TP + дата старта (`club_races`), ручное подтверждение тренера (`coach_confirmed`), протокол probeg.org. См. `docs/records-root-cause.md` и Блок 3.
