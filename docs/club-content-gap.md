# Club content-parity — GAP-список (ЭТАП 1)

Дата: 2026-07-29. Ветка: `feature/club-content-parity` (поверх текущих UI-правок `f4949b9`).
Задача: довести наполненность `/m/club` до уровня прежнего Run Club — состав и богатство
информации, дизайн НАШ.

**Метод.** Три эталонных экрана (карточка ленты, детальный экран, профиль участника)
разобраны поэлементно против ФАКТИЧЕСКОЙ модели данных клуба (типы `src/features/club/types.ts`,
сборщики `src/features/club/service.ts`, миграции кэша/FIT). Эталон — `docs/runclub-inventory.md`.

**Расхождение имён (для протокола).** Наряд ссылается на `docs/club-data-capabilities.md` —
такого файла нет. Ближайшее — `docs/runclub-inventory.md` (фиче-триаж переноса, не
поэлементный вердикт полей). Этот gap-список и есть недостающий поэлементный разбор; собран
заново на реальной модели, Run Club повторно не разбирался.

## Легенда корзин
- **A** — данные есть, делаем сейчас.
- **B** — можно после доработки (новый источник/поле/таблица/сервис); реализуем только по слову Игоря.
- **C** — невозможно, с причиной.
- **D** — продуктовое решение, не техническое: решает Игорь.

## Где что лежит (факт, с цитатами)
- Кэш `trainingpeaks_workout_cache` (миграция `20260518101000`): `workout_date`, `title`,
  коды спорта, `is_planned/is_completed`, `completed_time_raw` (часы→сек), `completed_distance_raw`,
  **`start_time` (free TEXT, стр. 21)**. HR / высоты / каденса / координат в кэше НЕТ.
  Читается через `WORKOUT_CACHE_COLUMNS` (`service.ts:354`).
- Круги `trainingpeaks_workout_laps` (`20260709160000`): `pace_sec_per_km`, `avg_hr`, `max_hr`,
  `avg_cadence`, `timer_time_s` (moving) vs `elapsed_time_s`, `distance_m`,
  **`total_ascent_m` / `total_descent_m` по кругам (стр. 36–37)**. Детальный select уже читает
  `total_ascent_m` (`service.ts:2603`), но `ClubWorkoutLap` его не выдаёт.
- Derived `trainingpeaks_workout_derived_metrics`: `avg_hr` (очищенный), `hr_trusted`,
  `time_in_zones` (jsonb), `zone_basis`. Высоты на уровне тренировки НЕТ — только сумма по кругам.
- Треки `trainingpeaks_workout_tracks` (`20260803000000`): `polyline` (jsonb `[lat,lng]`), `bbox`,
  `point_count`. За флагом `CLUB_TRACKS_ENABLED`. **Только новые тренировки** — старые не бэкфиллятся.
- Посекундные ряды (пульс/темп/каденс/высота) парсер строит транзитно (`NormalizedFitRecord`,
  `fit-workout-normalization.ts:23-31`) и ВЫБРАСЫВАЕТ после расчёта сводных — таблицы рядов НЕТ.
- `photo_url` из Telegram НЕ захватывается: `TelegramInitDataUser` = `{id, firstName, lastName,
  username}` (`validate-init-data.ts:209-214`), `getUserProfilePhotos` не вызывается нигде. Аватары = монограммы.

## Корзина B — свод (детальные оценки — в отчёте ЭТАП 3, здесь тег + суть)
- **B №1 Аватары.** `photo_url` из initData не читается; `getUserProfilePhotos` не зовётся.
  Нужно: захват фото + хранение + обновление + приватность. Самое заметное отличие.
- **B №2 Посекундные ряды.** Парсер строит и выбрасывает; нет таблицы. Нужно: схема + правка
  ингеста + оценка объёма/времени. Даёт гладкие графики вместо ступенчатых. Только НОВЫЕ тренировки.
- **B №3 Город тренировки.** Координаты новых тренировок есть (`tracks.polyline`); нужен реверс-геокодинг (внешний сервис: лимиты/стоимость/приватность).

## Корзина C — невозможно
- Гладкий посекундный профиль высоты/пульса для СТАРЫХ тренировок — ряды не хранились, трек не бэкфиллится.
- Пользовательские фото тренировки — в TP-кэше нет источника.

## Корзина D — решает Игорь
- **D №1 XP / уровни / ранги** — своя механика клуба (челлендж, красавчики, серии, ачивки). Оценка «за/против» — ЭТАП 4.
- **D №2 Чужие старты/достижения на публичном профиле** — приватность: показывать ли другим ученикам заявленные старты и ачивки участника.

## Итог ЭТАПА 1
Богатство эталона достигается в основном на УЖЕ имеющихся данных (корзина A): инсайт-плашка и
время суток в ленте, ступенчатый профиль высоты и графики по кругам в детали, обогащённый
профиль участника (дата вступления, 7-дневная полоска, расширенная 30-дневка, старты,
достижения). Три настоящих ограничения — в B (аватары, посекундные ряды, город) и требуют
слова Игоря. Реализуем корзину A (ЭТАП 2), B/C/D — описываем.
