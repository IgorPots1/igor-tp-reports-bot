# Гоночные карточки: наряд и эталон

Папка описывает, как делать **карточки гоночных раскладок** для учеников Игоря:
персональный PDF на один старт (цель, темп по километрам, рельеф, питание,
разминка, три напоминания).

Карточка уходит ученику в Telegram **от имени тренера**, поэтому цена ошибки
высокая: неверное время старта или выдуманный профиль трассы попадут прямо
человеку перед забегом.

## С чего начать новой сессии

1. Прочитай `card-standard.md` — это **эталон**. Там структура карточки,
   тон, жёсткие запреты и методика расчёта темпа. Без него не начинай.
2. Прочитай `research-brief.md` — это **наряд на разведку**: что искать
   по каждому старту, где стоп-краны, что уже подтверждено (не переделывай).
3. Возьми конвейер из `pipeline/`: `_style.css`, `template.html`, `gen.cjs`.
   Он рендерит HTML в PDF ровно в том виде, который согласован с Игорем.
   Разовая подготовка: `mkdir -p ~/cards && cd ~/cards && npm init -y && npm i puppeteer-core`.
4. Форму спортсмена тяни запросами из `queries.sql` (Supabase MCP,
   проект `igor-agent-hub`). Персональные данные в репозиторий **не класть**.

## Порядок работы

```
разведка трассы  →  форма из Supabase  →  расчёт темпа  →  HTML по эталону
     →  рендер gen.js  →  визуальная проверка PNG  →  отдать Игорю PDF
```

Игорь проверяет и правит. Ученику ничего не отправляем: **карточки
отдаются только тренеру**, он рассылает сам.

## Чего делать нельзя

- Не отправлять сообщения ученикам ни при каких условиях.
- Не писать в карточку непроверенные факты (см. `card-standard.md`).
- Не коммитить персональные данные учеников: имена в связке с темпами,
  пульсом, результатами. Данные живут в Supabase, здесь только запросы.
