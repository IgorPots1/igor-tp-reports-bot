# Движок физиологии

Слой аналитики поверх lap-данных TrainingPeaks. Считает то, чего нет в самом
TrainingPeaks: критическую скорость и анаэробный резерв, durability, готовность
по вариабельности пульса и радар внимания тренера по всей группе.

Вся математика живёт в базе (Supabase `igor-agent-hub`), в приложении — только чтение витрин.

## Объекты в базе

Все с префиксом `physio_`. RLS включён на всех таблицах, политик нет —
доступ только через `service_role`, то есть с сервера.

**Таблицы**

- `physio_effort_points` — лучшие однородные максимальные отрезки по бакетам длительности
- `physio_profiles` — критическая скорость, D′, зоны, VDOT, прогнозы, durability
- `physio_durability_samples` — поквартильный разбор длинных работ
- `physio_readiness_daily` — готовность по ln(RMSSD), пульсу покоя и сну
- `physio_load_daily` — TRIMP, CTL/ATL/TSB, ACWR, монотонность
- `physio_alerts` — радар внимания
- `physio_glossary` — человеческие формулировки, правятся без деплоя
- `physio_engine_runs` — журнал прогонов

**Витрины**

- `physio_coach_radar` — радар с контекстом и признаком «причина известна»
- `physio_athlete_overview` — карточка ученика
- `physio_student_context_items` / `physio_student_context_state` — контекст из переписки и питания
- `physio_data_health` — полнота данных по каждому ученику
- `physio_coverage_gaps` — почему у ученика нет профиля

**Функции**

- `physio_refresh_all(p_window_days, p_days)` — полный пересчёт, около 40 секунд
- `physio_group_summary()` — сводка для шапки

## Миграции

19 миграций с префиксом `physio_` **уже применены на проде** напрямую через Supabase MCP
и записаны в `supabase_migrations.schema_migrations`. Файлов в `supabase/migrations/`
для них нет — чтобы их материализовать и выровнять историю, достаточно один раз выполнить:

```bash
supabase db pull
```

Команда вытянет их из удалённой истории как обычные файлы. Применять ничего не нужно,
на проде они уже стоят.

## Регулярный пересчёт

Сейчас пересчёт ручной. Чтобы он шёл сам после ночной выгрузки TrainingPeaks:

```sql
select cron.schedule('physio-refresh', '0 4 * * *', $$select physio_refresh_all(180, 400)$$);
```

Проверить последний прогон:

```sql
select started_at, finished_at, status, stats, error
from physio_engine_runs order by started_at desc limit 5;
```

## Что важно понимать про цифры

1. **Критическая скорость занижена.** Точки кривой берутся из обычных тренировок, а не из
   контрольных тестов. Это честно записано в `quality_reasons` каждого профиля и показывается
   в интерфейсе. Лечится контрольным тестом раз в 6–8 недель: 3-минутный максимум или
   связка 1200/2400/3600 м.
2. **Пороги декаплинга — инженерная эвристика**, не результат РКИ. Медиана по этой группе
   (около 5.3% в час) полезнее абсолютных порогов из литературы.
3. **ACWR методологически спорен** даже в несвязанном варианте (Impellizzeri 2020). Считается
   как один из сигналов, не как приговор. Алерты по нему не выдаются, пока история короче 42 дней.
4. **Готовность без HRV — это `partial`, а не `green`.** Отсутствие данных не выдаётся за
   хорошую новость. Кто именно не отдаёт данные — видно во вкладке «Данные».

Радар только сигнализирует. Никаких автоматических действий с учеником движок не делает.
