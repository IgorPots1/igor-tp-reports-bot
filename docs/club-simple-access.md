# Упрощённый вход в /m/club — диагностика + автопривязка

Ветка `feature/club-simple-access`. Без push/деплоев, миграции файлами, ученикам ничего не уходит.

## 0. ПОЧИНКА АВТОРИЗАЦИИ (initData не доезжал) — СДЕЛАНО

**Причина (по коду):** Telegram Web App SDK грузится `<Script strategy="beforeInteractive">` в
**нероутовом** `src/app/m/layout.tsx`. В Next.js `beforeInteractive` действует ТОЛЬКО в корневом
`app/layout.tsx`; в нероутовом скрипт грузится позже. Клубный `useEffect` читал
`window.Telegram.WebApp` ОДИН раз на маунте — если SDK ещё не загружен, `tg=null` →
`setInitData("")` навсегда → каждый запрос слал пустой initData → **401 unauthorized у всех**.
Ретрая не было.

**Правка (`src/app/m/club/page.tsx`):** опрос initData каждые 50 мс до ~2 с, пока SDK не отдаст
непустой initData; иначе — сдаёмся (реальное открытие вне Telegram). Скрипт /m/layout не трогал.
Без этого весь клуб бессмысленен — теперь привязанный ученик реально попадёт в ленту.

## 2. АВТОПРИВЯЗКА ПО ИЗВЕСТНЫМ ID — 92 из 95 (dry-run, НЕ применял)

**Открытие:** у Telegram для приватного 1:1 чата `chat.id == user.id`. В `trainingpeaks_students`
уже есть `telegram_chat_id` (из Business DM) у почти всех. **Проверено на данных: у 17/17 уже
привязанных `telegram_chat_id == telegram_user_id` — равенство доказано, 0 исключений.**

Значит непривязанного с приватным numeric `telegram_chat_id` можно привязать как
`telegram_user_id = telegram_chat_id` с высокой уверенностью.

| Метрика | Значение |
|---|---|
| Активных учеников (не сервисных) | 112 |
| Привязано сейчас | 17 |
| Непривязано | 95 |
| **Автопривязка (однозначно)** | **92** |
| Коллизии (chat_id уже занят) | 0 |
| Общий chat_id у двух строк | 0 |
| **На ручное решение** | **3** — Svetlana Fadeeva, Irina Melnikova, Valentin Shavkun (нет приватного chat_id) |

**Скрипт:** `scripts/club-autobind-dryrun.ts` (`npm run club-autobind-dryrun`) — read-only, печатает
`ученик / telegram_id / источник / уверенность`. Применение — только с флагом `--apply` (**запускаешь
ты**), привязывает лишь однозначные, только там где `telegram_user_id` сейчас NULL.

**Следствие для остального наряда:** автопривязка снимает 92 из 95 сразу. Заявочная система (п.3–5)
нужна лишь для **3 оставшихся вручную + будущих новых** участников — объём резко падает.

## Заявочная система — РЕАЛИЗОВАНО (парты 1, 3, 4, 5)

**1. Общая ссылка / токены за флагом.** Резолвер: непривязанный без валидного токена → заявка.
Токен-путь (/admin/club/links, персональные ссылки) оставлен в коде за `CLUB_LINK_TOKENS_ENABLED`
(ВЫКЛ) — из основного сценария убран. Общая ссылка `t.me/igor_agent_hub_bot/XOclub`.

**3. Заявка на доступ.** Миграция-файл `20260729000000_club_access_requests.sql` (не применять):
telegram_user_id (unique), username, first_name, last_name, status, student_id, handled_by/at.
`resolveClubStudent`: непривязанный → `recordClubAccessRequest` (upsert по telegram_user_id, дубль
НЕ создаётся) → код `needs_request` «Заявка отправлена — тренер подтвердит доступ», данных клуба нет.
После одобрения тренером `existing` найдётся → сразу лента.

**4. Экран `/admin/club/requests`** (+ ссылка в индексе клуба). По каждой заявке: Telegram-имя,
@username, id, время. Автоподсказка — топ-3 похожих ученика (нечёткое имя, Cyrillic→Latin) кнопками
в один тап. Полный дропдаун кандидатов с деталями (см. 4.2). Кнопка «Отклонить». Всё в club_link_events.

**4.1 Привязка = Telegram + TP одним действием — ДА.** TP-идентификатор атлета — колонка
`trainingpeaks_students.student_id` (text; НЕ `trainingpeaks_athlete_id` — такой нет). **Уникальна:
112 distinct на 112 активных, 0 пропусков, 0 дублей.** `id` (uuid) — локальный ключ. Привязка
`telegram_user_id` к строке связывает человека и с TP-аккаунтом — отдельной сущности не нужно.

**4.2 В карточке кандидата** (label дропдауна и кнопок): имя · TP{student_id} · последняя тренировка ·
30д-счётчик · метки АРХИВ/СЕРВИС/ЗАНЯТ/ДУБЛЬ-TP. Мёртвая строка (30д=0, старая дата) видна сразу.

**4.3 Защита от неверного сопоставления.** Архивные/сервисные в подсказки НЕ идут (только active
non-service), в дропдауне — внизу с меткой. Дубли TP-строк помечаются (в данных сейчас 0). Кандидаты
без TP-id — помечены (сейчас 0).

**4.4 Сводка после привязки.** approve-action возвращает нотис: «Привязано: Имя. Последняя
тренировка: дата, за 7 дней: N» + «⚠ пусто — проверь, та ли строка», если 7д=0.

**5. Защита.** Привязка через `linkTelegramUserIdToStudent` (collision-safe): занятый Telegram/ученик
→ блок, лог conflict, видно в админке. Ученик себя не выбирает и списка не видит. Отвязка — тренером.
