# Упрощённый вход в /m/club — диагностика + автопривязка

Ветка `feature/club-simple-access`. Без push/деплоев, миграции файлами, ученикам ничего не уходит.

## 0. ПОЧИНКА АВТОРИЗАЦИИ (initData не доезжал) — СДЕЛАНО

**Причина (по коду):** Telegram Web App SDK грузится `<Script strategy="beforeInteractive">` в
**нероутовом** `src/app/m/layout.tsx`. В Next.js `beforeInteractive` действует ТОЛЬКО в корневом
`app/layout.tsx`; в нероутовом скрипт грузится позже. Клубный `useEffect` читал
`window.Telegram.WebApp` ОДИН раз на маунте — если SDK ещё не загружен, `tg=null` →
`setInitData("")` навсегда → каждый запрос слал пустой initData → **401 unauthorized у всех**.
Ретрая не было.

**Правка (`src/app/m/club/page.tsx`):** опрос initData каждые 50 мс до ~2 с, пока SDK не отдаст
непустой initData; иначе — сдаёмся (реальное открытие вне Telegram). Скрипт /m/layout не трогал.
Без этого весь клуб бессмысленен — теперь привязанный ученик реально попадёт в ленту.

## 2. АВТОПРИВЯЗКА ПО ИЗВЕСТНЫМ ID — 92 из 95 (dry-run, НЕ применял)

**Открытие:** у Telegram для приватного 1:1 чата `chat.id == user.id`. В `trainingpeaks_students`
уже есть `telegram_chat_id` (из Business DM) у почти всех. **Проверено на данных: у 17/17 уже
привязанных `telegram_chat_id == telegram_user_id` — равенство доказано, 0 исключений.**

Значит непривязанного с приватным numeric `telegram_chat_id` можно привязать как
`telegram_user_id = telegram_chat_id` с высокой уверенностью.

| Метрика | Значение |
|---|---|
| Активных учеников (не сервисных) | 112 |
| Привязано сейчас | 17 |
| Непривязано | 95 |
| **Автопривязка (однозначно)** | **92** |
| Коллизии (chat_id уже занят) | 0 |
| Общий chat_id у двух строк | 0 |
| **На ручное решение** | **3** — Svetlana Fadeeva, Irina Melnikova, Valentin Shavkun (нет приватного chat_id) |

**Скрипт:** `scripts/club-autobind-dryrun.ts` (`npm run club-autobind-dryrun`) — read-only, печатает
`ученик / telegram_id / источник / уверенность`. Применение — только с флагом `--apply` (**запускаешь
ты**), привязывает лишь однозначные, только там где `telegram_user_id` сейчас NULL.

**Следствие для остального наряда:** автопривязка снимает 92 из 95 сразу. Заявочная система (п.3–5)
нужна лишь для **3 оставшихся вручную + будущих новых** участников — объём резко падает.

## 4.1 Привязка = Telegram + TrainingPeaks одним действием — ДА

`trainingpeaks_students.trainingpeaks_athlete_id` (bigint) — уникальный TP-идентификатор атлета.
Строка ученика ОДНОЗНАЧНО соответствует TP-аккаунту. Привязка `telegram_user_id` к этой строке
связывает человека и с TP — отдельной сущности не нужно. (Подтверждение в отчёте, поле проверено
в схеме.)
