# Точка входа в /m/club — безопасные одноразовые ссылки

Ветка `feature/club-entry-links`. Без push/деплоев, миграция файлом (не применять),
ученикам НИЧЕГО не отправляется, BotFather не трогается.

## Проблема и решение

`/m/n` кладёт `studentRowId` прямо в `startapp` — для клуба небезопасно: ссылка уйдёт
в общий чат, будет пересылаться, а открывший может подтвердить «это я» и привязаться к
чужой строке (привязка одноразовая, чинит только тренер). Клуб теперь носит **непрозрачный
одноразовый ТОКЕН**:

- **opaque** — 32 hex-символа, не угадать и не нацелить на произвольного ученика (в отличие
  от rowId);
- **одноразовый** — сгорает после успешной привязки (`used_at`), пересланная уже-использованная
  ссылка мертва;
- **срок** — TTL по умолчанию 7 дней (`CLUB_LINK_TOKEN_TTL_DAYS`), потом невалиден;
- **отзываемый** — тренер гасит токен из админки;
- **подтверждение по имени** — экран показывает ТОЛЬКО имя (спека 2.1); случайно открывший
  жмёт «Это не я».

Тренер выдаёт ссылку ученику ЛИЧНО (не в группу). Автоотправки нет — только генерация и копирование.

## Миграция (файл, НЕ применять)

`supabase/migrations/20260728000000_club_link_tokens.sql` — таблица `club_link_tokens`
(token, student_id, expires_at, used_at, used_by_telegram_user_id, revoked_at, created_by,
created_at). Идемпотентна (`create table if not exists`), RLS ON, грант service_role.
Валидность: `used_at IS NULL AND revoked_at IS NULL AND expires_at > now()`.

## Короткое имя и формат ссылок

BotFather `/newapp` короткое имя клуба = **`club`** → env **`CLUB_MINIAPP_SHORT_NAME`**.
Билдер `src/features/club/entry-links.ts` (по образцу send-nutrition-form.ts, БЕЗ отправки):
- Личная: `https://t.me/<bot>/club?startapp=<token>` (непривязанному).
- Общая: `https://t.me/<bot>/club` (уже привязанному).
Сам BotFather-шаг делает тренер — вне кода.

## Админка `/admin/club/links`

- «Сгенерировать ссылку» на ученика → активный токен + готовая ссылка для копирования + срок + «Отозвать».
- «Сгенерировать всем непривязанным» (массово) → блок-экспорт `Имя → ссылка` (textarea) для ручной рассылки.
- Общая ссылка без параметра — отдельным блоком, для уже привязанных.
- **Автоотправки ученикам НЕТ.** Только генерация и копирование.
- Если `CLUB_MINIAPP_SHORT_NAME`/бот не настроены — токены генерируются, но ссылка не строится
  (громкий баннер), rowId никуда не утекает.

## Проверка путей (трейс по коду)

| Сценарий | Путь | Результат |
|---|---|---|
| **Привязанный, общая ссылка** (без токена) | `resolveClubStudent`: не тренер → `existing` найден → token=null → `ok(existing)` | сразу лента (свои данные) ✅ |
| **Непривязанный, валидный токен** | `resolveClubStudent`: нет existing → token → `resolveClubLinkToken` ok → `needs_confirm{имя}`. Тап «Это я» → `confirm-link`: не тренер → нет existing → токен ok → `linkTelegramUserIdToStudent`=linked → `burnClubLinkToken` (used_at) → лог `confirmed/token_first_open` → ok | экран подтверждения (только имя) → привязка → лента; **токен сгорел** ✅ |
| **Непривязанный, без токена** | `resolveClubStudent`: нет existing → token=null → `needs_link` | «Открой клуб по личной ссылке от тренера»; данных нет ✅ |
| **Токен использован/просрочен/отозван/чужой (непривязанный)** | `resolveClubLinkToken` → reason(used/expired/revoked/not_found) → `invalid_link` | «Ссылка недействительна, обратись к тренеру»; **данные ученика не показываются** ✅ |
| **Использованную ссылку переслали, открыл другой** | не привязан → токен `used` → `invalid_link` | отказ, данных нет ✅ |
| **Тренерский аккаунт** | `resolveClubStudent`: chat id в coach list → 403 `coach_account` | «Это тренерский аккаунт…», как сейчас ✅ |
| **Привязанный открыл чужую валидную ссылку** | existing есть, токен → другой student → `wrong_target` | «Эта ссылка для другого аккаунта»; свои данные не подменяются ✅ |

Замечание по границе безопасности: токен — это bearer-секрет. Первый, кто откроет ещё-НЕ-
использованный токен, технически может привязаться (поэтому экран показывает имя для «Это не я»,
а тренер шлёт ссылку лично). Модель гарантирует: нельзя нацелить произвольного ученика (opaque),
пересланная после использования ссылка мертва (one-time), протухает (TTL) и отзывается. Это и есть
защита против «уйдёт в общий чат и будет пересылаться».

Совместимость: общий резолвер `/m/n` (`resolveMiniAppStudent`) НЕ тронут — клуб больше им не
пользуется для привязки (свой токен-путь в `confirm-link`).
