# Рекорды: корневая причина (алгоритм или данные)

Сгенерировано `scripts/records-diagnosis.ts` (read-only). Без ФИО.

## Вердикт (одной фразой)

**ПРОБЛЕМА В ДАННЫХ: забегов в кэше нет (0 записей на даты стартов), рекорды — лучшие отрезки лёгких пробежек, их темп близок к обычному недельному. Алгоритм выбирает лучшее из имеющегося.**

## Доказательства

- Рекордов всего: **86** → тип **race 0**, **training_split 86** (race = дата рекорда совпала с объявленным стартом в club_races).
- Темп рекорда ≈ обычный недельный (в пределах 5%): **44** из 86 → это лёгкие пробежки, не гонки.
- Источник — длинная пробежка (полная запись > 1.5× дистанции): **39**.
- Посчитано методом «вся тренировка» (нет сплита): **10**.

### Распределение темпа выбранных рекордов по дистанции

- 5k: n=50, темп мин 4:17 · медиана 5:57 · макс 8:34 /км
- 10k: n=32, темп мин 4:19 · медиана 5:46 · макс 8:01 /км
- 21k: n=4, темп мин 3:19 · медиана 5:31 · макс 5:52 /км
- 42k: нет

### Проверка «10 км ≈ 60 мин»: константа или просто похоже

- Значений 10k всего: 32; попадают в 59:00–61:00: **6**.
- Одинаковых значений (точное совпадение секунд) нет → это НЕ константа/дефолт в коде, а просто похожие реальные лёгкие пробежки у разных людей.

Итог: якорь E-Predictor можно строить только на настоящих гонках. Пока их нет в кэше — рекорды остаются оценкой по тренировкам (training_split) и в клубные топы не идут.
