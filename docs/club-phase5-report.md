# Club Phase 5 — календарь на 45 дней (отчёт)

Ветка `feature/club-calendar`, **застекована на `feature/club-tracks`** (→ phase3 → tracks → calendar).
Всё за флагом `CLUB_CALENDAR_ENABLED` (ВЫКЛ). Ничего не пишется в TrainingPeaks (это Фаза 11).
Заявки уходят только в инбокс тренера; ученикам ничего не отправляется.

## Единая структура (основа автопланировщика — задел под Фазу 11.2)
Новая таблица `club_calendar_entries` (миграция `20260804000000`, НЕ применена) — ОДНА
машиночитаемая таблица на всё, что ученик отмечает на будущий день:
`kind ∈ {day_off, preference, note, race}`, `preferred_workout_type ∈ {long, intervals, rest}`,
`note`, поля забега (`race_name/city/distance_label/target_seconds`), `status`, `source`, дата.
- day_off/preference — один-на-день (partial unique index → upsert, не дубли); note/race — можно
  несколько.
- Интерфейс автопланировщика: `getStudentDateConstraints(studentId, date)` — возвращает
  `{dayOff, preferredType, notes[], races[]}` по approved/applied записям одним запросом.
  Именно этим Фаза 11 и будущий планировщик спросят «какие ограничения у ученика на дату X».
- Существующие `club_dayoff_requests / club_wishes / club_races` НЕ удалены (back-compat, старые
  разделы кабинета работают), но календарь — новая первичная поверхность.

## 5.1 Календарь (мини-апп)
`CalendarOverlay` (открывается из профиля, карточка «Календарь на 45 дней»): сетка 45 дней вперёд,
выровнена по дням недели, сегодня подсвечен, на днях — маркеры (🛌 выходной, 🎯 пожелание, 📝 заметка,
🏁 забег). Тап по дню → редактор дня.

## 5.2 Форма забега (все поля на одном экране)
В редакторе дня: **точное название (обязательно)**, город, дистанция, целевое время (чч:мм:сс),
пожелания. Ссылку не требуем.

## 5.3 Предпочтение по типу на день
Чипы: Длительная / Интервальная / Отдых (силовые НЕ включены). Один-на-день (перезапись).

## 5.4 Общие пожелания по процессу — отдельно
Внизу оверлея отдельное свободное поле «Общие пожелания по процессу» → уходит в существующий
`club_wishes` (note), отдельно от дневных заметок.

## 5.5 Инбокс тренера + календарь клуба на 45 дней + пакетное подтверждение
- Repository: `listClubCalendarAdmin()` (все записи на 45 дней вперёд + имена учеников),
  `setCalendarEntryStatus(id, status)`, `approveAllPendingCalendar()`.
- Страница `/admin/club/calendar`: заявки сгруппированы по дням (кто что запросил), у каждой pending —
  ✓/✕, сверху «Подтвердить все N». Ссылка добавлена на индексе `/admin/club`.
- Статусы: pending → approved | rejected. `applied` зарезервирован под Фазу 11 (запись в TP).

## 5.6 Флаги
`CLUB_CALENDAR_ENABLED` (ВЫКЛ) — мастер-флаг календаря. Существующие `CLUB_DAYOFF_ENABLED`,
`CLUB_WISHES_ENABLED`, `CLUB_RACES_ENABLED` остаются ВЫКЛ (старые разделы кабинета). Ученик правит
только свои pending-записи (удаление своей pending), авторизация из initData-резолвера, не с клиента.
