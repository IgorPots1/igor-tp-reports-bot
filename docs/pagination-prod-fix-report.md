`src/features/supabase/paginate.ts`:

## BLOCK 1 — уже испорченные данные (память тренера)
- **1.1 диагностика** (`docs/coach-memory-dupes.md`): баг реальный, но **латентный** — материального дублирования почти нет (таблица 848 строк < 1000 → «уже влитые» читаются одной страницей). Истинных дублей (одинаковые student+source+type): **6, все с РАЗНЫМ текстом** (точных копий 0); почти все — легитимные многофактовые извлечения из одного сообщения.
- **1.2 фикс:** `backfill-coach-memory-v1.ts:511` pageSize 5000→**1000** + `.order("id")`. Раньше первая страница возвращала 1000 < 5000 → цикл рвался после 1-й → часть влитых считалась новой → повторный ингест. Теперь читает целиком при любом размере.
- **1.3 дедуп (НЕ запускать):** `scripts/dedupe-coach-memory-dry-run.ts` — консервативный, удаляет только ТОЧНЫЕ копии (student+source+type+text), оставляя раннюю. Прогон: **0 к удалению**. Пограничные (разный текст) не трогает — рука Игоря.

## BLOCK 2 — контент ученику (🔴 подтверждённое искажение)
Общая точка — `fetchIn()` в `feedback-enqueue.ts`: теперь чанкует по 150 И листает каждый чанк (`.order("id").range()`). Из вызовов убраны `.limit(6000/40000/8000/4000)` (они резали до 1000).

- **2.1 laps (`:182`):** ВСЕ 123 свежие цели сидели в чанках, превышавших 1000 → их `avgPaceSecPerKm`/`durationS` считались на НЕПОЛНЫХ лапах. **Вывод: часть уже отправленных ученикам черновиков содержала неверные темп/длительность.** Починено.
- **2.2 history/health (`:114/:159`):** норма сравнения строилась на **11%** истории, health-baseline на **2%**. Починено — теперь на полных.
- ⚠️ **ПЕРФ-БЛОКЕР (требует твоего решения ДО деплоя):** health-чтение (`:159`) не имеет фильтра по дате — на полных данных это **~51 000 строк за свип** (у health нет окна). Я НЕ добавлял дату (это логика, вне «только полнота»). Рекомендация: отдельным нарядом сузить health/history до окна, которое реально использует потребитель (сравнение ~8–12 недель, health ~90 дней) — тогда полно И дёшево. Сейчас свип фоновый (cron), ~156k строк/прогон листается за ~20–30с — вероятно терпимо, но перед деплоем подтверди или дай добро на окно.
- **2.3 recency канал (`repository.ts:3268`):** читал 1 000 из 8 567 обзерваций (12%). После фикса: у **27 учеников** изменился `lastBusinessDmAt`, у **1** — групповой сигнал. **НО выбор канала сегодня НЕ менялся: 0 учеников пересекли порог 24ч** (сортировка desc всегда сохраняла свежайшие ≤24ч; усечение резало только СТАРЫЕ сообщения). То есть баг НЕ слал не туда сегодня; фикс — полнота + защита группового сигнала + запас на рост. Ничего не отправлял.

## BLOCK 3 — остальное (🟠)
