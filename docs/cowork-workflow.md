# Cowork workflow (как Игорь + Claude катят изменения)

Короткая памятка процесса, чтобы не возиться с PR/мержами на GitHub.
Репозиторий боевой (реальные ученики, платежи, TrainingPeaks) — поэтому финальный
push в прод всегда делает Игорь, а вся работа и проверки на стороне Claude.

## Обычный поток (фича с проверкой на preview)

1. **Claude** делает фичу в отдельной ветке, коммитит, прогоняет проверки
   (`npm run lint`, `npx tsc --noEmit`, относящиеся `check-*`-скрипты).
2. **Игорь** пушит ветку одной командой:
   ```bash
   git push -u origin <ветка>
   ```
   Vercel автоматически собирает **preview-деплой** ветки.
3. **Игорь** смотрит preview (для мелких/безопасных правок шаг можно пропустить).
4. Если ок — **Claude** локально делает **fast-forward** `main` на ветку
   (без merge-коммита), **Игорь** один раз пушит прод:
   ```bash
   git checkout main
   git push origin main
   ```
   Прод деплоится из `main` автоматически.

Итого от Игоря — максимум **2 команды `git push`** на фичу. Никаких
Create PR / Merge / Confirm / Delete branch.

Для совсем мелких безопасных правок можно без ветки: Claude коммитит, делает
fast-forward `main`, Игорь пушит `main` один раз.

## Откат

- Если ветку влили fast-forward — откат: `git revert <commit>...` нужных коммитов
  и `git push origin main`.
- Если был merge-коммит — `git revert -m 1 <merge-commit>` + push.

## Миграции БД

- Claude **не запускает** прод-миграции сам.
- Если изменение требует новой таблицы/колонки, Claude: (1) явно говорит
  «нужна миграция», (2) кладёт файл в `supabase/migrations/`, (3) даёт команду
  применить. Миграцию применять **до** деплоя кода, который на неё опирается.

## Безопасность (из CLAUDE.md)

- Без секретов в чате; `.env*` не трогаем.
- Биллинг/Telegram/TrainingPeaks — чувствительные зоны: предпочитаем dry-run,
  ручное подтверждение, изменения узкие и обратимые.
- Параллельно с активной сессией Claude лучше не давать Cursor делать git-операции
  (коммиты/checkout) — общий рабочий каталог, коммиты могут «прилипать» к чужой ветке.
