# Открытые вопросы и выбранные дефолты — Mini App «Клуб»

Формат: вопрос / выбранный дефолт / что поменяется, если ответ другой. Работаю автономно на дефолтах, здесь — точки для последующей ревизии Игорем.

---

### 1. Стилистика: «как /m/desk» vs «тёмная/жёлтая/Oswald»
- **Вопрос.** Наряд одновременно требует «стилистика как /m/desk» и «тёмная тема, жёлтый акцент, Oswald + Montserrat». Реальный `/m/desk` — светло-бирюзовый (`#1D9E75`), только Montserrat, без Oswald. Это противоречие.
- **Дефолт.** Технические конвенции беру от `/m/desk` (inline-стили, Telegram init, tab-bar, initData). Палитру — по явным токенам наряда: тёмная тема + жёлтый акцент + Oswald (заголовки) + Montserrat (текст). Клуб получает свою «клубную» айдентику, `/m/desk` не трогаю.
- **Если иначе.** Если нужно 1:1 как desk (светло-бирюзовый, только Montserrat) — меняется только объект токенов `C` в `src/app/m/club/page.tsx` и убирается локальный Oswald-layout. UI-логика не меняется.

### 2. Аудитория мини-аппа
- **Вопрос.** Клуб для тренера (админ) или для учеников?
- **Дефолт.** Ученическая поверхность: ученик видит клубную ленту/топы и свой личный кабинет. Резолвер — `resolveMiniAppStudent`. Изолировано от `/m/desk` (тренер) и `/m/n` (питание).
- **Если иначе.** Если это тренерский обзор — поменять резолвер на `resolveMiniAppCoach` и снять фильтр приватности/сервисных аккаунтов (тренер видит всех).

### 3. Отображаемое имя в ленте
- **Вопрос.** Как показывать имя ученика другим.
- **Дефолт.** Первое слово `student_name` (имя без фамилии) + монограмма (аватара в схеме нет).
- **Если иначе.** Полное имя / ник — поменять `toDisplayName()` в сервисе. Ник потребует новой колонки.

### 4. Цель клубного челленджа (км)
- **Вопрос.** Откуда берётся целевой километраж клуба. В Coach OS нет таблицы челленджей/целей.
- **Дефолт.** Цель — конфиг-константа/фикстура (`src/features/club/constants.ts` + `fixtures/`), помечена как фикстура (`goalIsFixture: true`), в проде цифры не выдумываю — показываю с пометкой «демо-цель». Прогресс (клубный км) — реальный.
- **Если иначе.** Реальная цель → нужна мини-таблица `club_challenges` (goal_km, period) или env-переменная. Дам миграцию-файл при подтверждении.

### 5. Часовой пояс недельного окна
- **Вопрос.** По какому TZ считать «неделю» для км/красавчиков/серии.
- **Дефолт.** Europe/Belgrade (в проекте есть `BELGRADE_TIMEZONE`), ISO-неделя (пн–вс). Гонка недели Run Club была Europe/Moscow — но это другой проект.
- **Если иначе.** Другой TZ/старт недели — одна константа в `constants.ts`.

### 6. Порог «надёжности» рекорда
- **Вопрос.** Когда рекорд «надёжный», а когда «предварительный».
- **Дефолт.** Полоса дистанции ±0.5 км (по наряду). «Надёжный», если есть laps с темпом и CV темпа ≤ 0.08, ИЛИ дистанция в узкой полосе ±0.15 км. 5k всегда «предварительно» (по наряду). Иначе — «предварительно».
- **Если иначе.** Другой порог CV/полосы — константы в `constants.ts`. Если laps почти нигде не заполнены — рекорды массово «предварительные», честно помечаем (цифры не подделываем).

### 7. Ручное обновление данных из мини-аппа
- **Вопрос.** Нужна ли кнопка «обновить сейчас» (тянуть свежее из TP).
- **Дефолт.** Нет. Клуб read-only, едет на существующем ежечасном скане (`workout-cache-scan` + `fit-ingest-scan`). Показываю только индикатор свежести (`getTrainingPeaksWorkoutCacheFreshness`). Ручной скан — attended-операция тренера, вне ученической поверхности.
- **Если иначе.** Если нужен ручной триггер — это отдельный тренерский роут с гейтом, не из `/m/club`; спроектирую отдельно.

### 9. E-Predictor на джойне к кэшу (валидация рекордов)
- **Вопрос.** Есть ли per-athlete VDOT/порог, джойнящийся к тренировке на чтении, для сверки «результат быстрее прогноза → подозрительно».
- **Дефолт.** Недоступно: E-Predictor живёт в `tools/` (скрипты + `config/e-predictor-constants.json` + `src/app/tools/plan/vdot.ts`), не как per-student колонка. Взят fallback по наряду: сверка «против себя» — реконструированный VDOT кандидата сравнивается с медианным VDOT атлета по ДРУГИМ дистанциям; отрыв > 8 пунктов VDOT → `hidden` (`self_outlier`). Плюс абсолютный потолок темпа + целостность laps (паузы, сумма дистанций). Формула VDOT (Дэниелс) продублирована локально в `records.ts`.
- **Если иначе.** Если появится per-athlete якорь (напр. из `tp_zone_snapshots.threshold` → predicted times), подключить его в `evaluateCandidate` вместо/вместе с self-check. На реальных данных self_outlier поймал 3 кандидата.

### 10. Порог пауз (pause_gap) — агрессивность
- **Вопрос.** `elapsed/moving > 1.10 → hidden`. На реальных данных это дало 19 отбраковок из 23 — самая частая причина.
- **Дефолт.** 10% (`CLUB_RECORD_PAUSE_TOLERANCE`). Многие тренировки с остановками (светофоры, паузы) исключаются из рекордов как «не непрерывное усилие» — консервативно, по духу наряда «не уверен — не показывай».
- **Если иначе.** Если слишком строго (теряются валидные городские забеги) — поднять до 0.15–0.20. Одна константа.

### 11. records-validation.md содержит реальные имена/результаты учеников
- **Вопрос.** Артефакт валидации сохранён в git с реальными ФИО и временами.
- **Дефолт.** Сохранён как требует наряд (ключевой артефакт). Репозиторий приватный, уже содержит данные учеников.
- **Если иначе.** Если не хочешь это в истории git — добавь `docs/records-validation.md` в `.gitignore` или запускай скрипт локально без коммита вывода.

### 12. Стаб-флаги и цель челленджа по умолчанию
- **Дефолты (все ВЫКЛ, кроме режима цели):** `CLUB_REACTIONS_ENABLED`, `CLUB_PRIVACY_ENABLED`, `CLUB_STUBS_ENABLED` — ВЫКЛ. `CLUB_CHALLENGE_GOAL_MODE` — `auto` (прошлая неделя клуба ×1.1, округление до 10). Фикстура 500 — только крайний фолбэк, если прошлой недели нет данных.
- **Если иначе.** `manual` требует применить `club_challenges` + завести строку цели.

### 13. Спека v3 блок 2.1 (экран подтверждения регистрации) — нет в репозитории
- **Вопрос.** Наряд требует заменить молчаливую авто-привязку на явный экран «по спецификации v3 блок 2.1». Такой спеки в репозитории нет (`docs/specs/` отсутствует).
- **Дефолт.** Реализована клуб-скоуп явная привязка (peek `resolveClubStudent` + экран «Это ты? {Имя}» + `POST /api/m/club/confirm-link` как единственная точка бинда). Общий `resolveMiniAppStudent` (авто-бинд для /m/n) НЕ тронут. Детали и rollback SQL — `docs/miniapp-club-registration.md`.
- **Если иначе.** При появлении текста спеки v3 2.1 — подгоню формулировки/поток экрана. Логика бэкенда (peek + confirm) уже готова.

### 8. Реакции/лайки
- **Вопрос.** Нужны ли реакции в v1.
- **Дефолт.** Нет (по наряду) — только место в UI (задизейблено). Ничего не пишется, ничего не уходит ученикам.
- **Если иначе.** Включение реакций потребует таблицы `club_reactions` (миграция-файл) и роута — по отдельному наряду.
