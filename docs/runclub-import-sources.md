# Run Club импорт — ЭТАП 2: что брать (оценка, НЕ реализация)

Скрипт: `scripts/runclub-import-estimate.ts` (read-only). Считается по **41 уверенно сопоставленному**
ученику (ЭТАП 1: 28 точных + доминирующие подсказки по тренировкам). Транспорт (темп < 2:30/км)
отфильтрован во всех источниках, как для наших рекордов (README §5.1).

## 1. best_efforts — честные отрезки Strava (из потоков, не наша реконструкция)

**Достоверность: ВЫСОКАЯ.** Это отрезки, посчитанные Strava из GPS-потока активности, а не наша
реконструкция «лучшего окна» по лапам — источник точнее нашего.

| метрика | число |
|---|---|
| стандартных пар (ученик × 5K/10K/Half/Marathon) у сопоставленных | 113 |
| **НОВЫХ рекордов** (у нас на эту дистанцию пусто) | **78** |
| быстрее нашей реконструкции (можно улучшить) | 0 |
| защищено (coach_confirmed/official — Strava НЕ перебивает) | 35 |
| хуже/равно нашему | 0 |
| нестандартные отрезки (1K/1mile/15K/20K/30K/50k…) | 8850 сырых → **304 различных лучших** → в журнал |
| выброшено транспортом (быстрее 2:30/км) | 43 |

**Где разойдётся с нашим:** по сути нигде не конфликтует с реконструкцией — у этих 41 ученика наши
`club_records` это либо coach_confirmed/official (35, их не трогаем), либо ПУСТО (78 — Strava заполнит
дыры). «0 быстрее / 0 хуже» = реконструкции по ним у нас нет, Strava не спорит, а добирает.

**Что должно побеждать (для ЭТАПа 3):**
`coach_confirmed > official_protocol > race_events > strava_best_effort > реконструкция`.
Strava-отрезок честнее реконструкции → бьёт её, но НЕ верифицированные протоколы. Новый источник-ключ
`strava_best_effort`. Итого реально прибавит: **+78 стандартных рекордов + ~304 записи в журнал**
(нестандартные дистанции), без риска для подтверждённого.

## 2. map_polyline — координаты (наши треки только за 60 дней)

**Достоверность: ВЫСОКАЯ для данных, СРЕДНЯЯ по трудозатратам (схема).**

| метрика | число |
|---|---|
| пробежек с координатами у сопоставленных | 1990 |
| из них **старше ~60 дней** (net-new история за пределами наших треков) | **1053** |

**Как класть:** Strava отдаёт ЗАКОДИРОВАННУЮ полилинию (Google encoded) → декод в `[lat,lng][]` →
обрезка 300 м (`cropTrackForPrivacy`, та же, что для FIT) → Douglas-Peucker → `trainingpeaks_workout_tracks`.
Есть готовый `encodePolyline` (в track-maps.ts) — нужен обратный decode.

**⚠ Блокер схемы:** `trainingpeaks_workout_tracks` ключуется на `workout_cache_id` (TP-тренировка).
Strava-пробежки — не TP-тренировки, у них нет `workout_cache_id`. Значит нужен либо новый ключ/колонка
источника (`external_source='strava'` + `external_id`), либо параллельная таблица. Иначе 1053 трека
некуда положить. Это главное архитектурное решение ЭТАПа 3.
