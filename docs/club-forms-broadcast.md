# Club — рассылка форм из админки (первый исходящий путь клуба)

Экран `/admin/club/forms`. Тренер выбирает тип формы, правит текст, выбирает получателей,
жмёт «Отправить N» с подтверждением. **Ничего не уходит автоматически.**

## Флаг

`CLUB_FORMS_BROADCAST_ENABLED` (Vercel, ВЫКЛ по умолчанию). Пока ВЫКЛ — экран показывает
получателей, но отправка возвращает «выключено». Планировщика авто-рассылки НЕТ (сознательно).

## Отправка — от БОТА, не от business-аккаунта

Обычный `sendMessage` бота (без businessConnectionId), цель = `telegram_user_id` (личный чат
с ботом). Поэтому «кому дойдёт» = ученики с `telegram_user_id` (активные, не сервисные).
Сообщение: текст тренера + HTML-ссылка `t.me/<bot>/<app>?startapp=<section>`, открывающая
нужный раздел клуба сразу (не главный экран):
- `starts` → раздел «Старты» (проставить забеги);
- `schedule` → «Расписание» (выходные и пожелания на следующую неделю).

Deep-link читается в `src/app/m/club/page.tsx` (start_param → open section). Уже привязанный
ученик резолвится по `telegram_user_id`, так что section-код на вход не влияет.

## Надёжность

- Пауза `SEND_PAUSE_MS` между сообщениями (лимиты Telegram при ~110 получателях).
- Один сбой (бот не запущен / заблокирован / ошибка API) не останавливает рассылку — сбои
  собираются и показываются после («ошибок M: имена»).
- Каждая попытка логируется в `club_form_sends` (кому, что, когда, результат, ошибка).
- Таймаут функции не страшен: отправленные записаны, дедуп пропускает их при повторе — повтор
  просто дошлёт остаток. Либо слать частями через чекбоксы.

## Дедуп и напоминание

- Дедуп: тот же тип формы тому же ученику в тот же день не уходит второй раз (защита от
  двойного тапа) — по `club_form_sends`.
- «Напомнить не ответившим» (форма расписания): получатели считаются автоматически — кому
  отправляли расписание на неделю `target_week`, но кто НЕ создал ни одной записи в
  `club_calendar_entries` на эту неделю. Показывается, скольким и кому уйдёт.

## Что НЕ сделано (сознательно)

Авто-рассылки по расписанию нет. Флаг заложен, включение — рука тренера после обкатки ручной.

## Лог открытий клуба (было сломано)

До этого открытия НИГДЕ не хранились: `clientlog` писал только в консоль Vercel (не читается
из кода), `club_link_events` — это привязки, не открытия. Отсюда «~1 открытие» — отсутствие
логирования, а не отсутствие людей.

Теперь: таблица `club_open_events` (одна строка на ученика в день, upsert), пишется при КАЖДОМ
успешном резолве в клубном API (`resolveClubStudent`, best-effort, не валит запрос). В админке
`/admin/club/forms` — карточка «Открытия клуба»: уникальных за 7 дней, сегодня, всего, и список
кто/когда/с какого раздела. Появится после первых заходов (задним числом не восстановить).

## Онбординг-ссылка для общего чата (запускает бота)

Проблема: прямая ссылка на мини-апп (`t.me/<bot>/XOclub`) открывает приложение, но НЕ запускает
бота, а бот пишет только тем, кто его запустил. Решение — ссылка на БОТА с параметром:

`https://t.me/igorp_coach_bot?start=club`

Человек жмёт Старт → webhook ловит `/start club` (ДО coach-гейта, плайн-юзера не блокирует) →
если `telegram_user_id` известен, просто приветствие с кнопкой «Открыть клуб»; если нет — пишем
заявку в `club_access_requests` (тренер привяжет в `/admin/club/requests`), тоже приветствие +
кнопка. Главное: нажатие Старт даёт боту DM с человеком, и будущие рассылки форм до него дойдут.

Текст приветствия: env `CLUB_START_GREETING` (иначе дефолт в коде). Существующие `/start`
(`case_`/`action_`/`student_`, coach-меню) не тронуты — `club` был свободным параметром.
