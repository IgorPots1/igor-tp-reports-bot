## 1. Цель и контекст

Бесплатный инструмент, который по короткому видео бега с телефона выдаёт **детальный разбор техники**: углы, фазы, персональные рекомендации. Задача — не лабораторная точность, а **«быстрый скрин техники»**, который впечатляет и конвертирует лида в коучинг/клуб Игоря.

**Позиционирование:** ощущается как *вкус личного разбора от Игоря*, а не обезличенная апка. Тон отчёта — премиальный, человеческий, тренерский, на русском.

**Не обещаем** лабораторную/медицинскую точность. В интерфейсе честно: «экспресс-скрин, не замена очному анализу».

---

## 2. Объём v1

**Входит:**
- Один ракурс — **сбоку** (sagittal).
- Замер на устройстве пользователя (MediaPipe в браузере).
- Структурированный разбор от LLM (модель-агностичный слой).
- Отчёт с наложением скелета и метриками.
- Захват лида + передача события в ChatPlace-воронку.

**НЕ входит в v1 (бэклог):**
- Второй ракурс (сзади) — апселл/v2.
- Трекинг прогресса между загрузками.
- Аккаунты/история.
- Видеохранилище на сервере (см. раздел приватности).

---

## 3. Архитектура: гибрид (два слоя)

Точность дают **геометрия**, а смысл — **LLM**. Не отдавай измерение углов нейросети.

```
Видео → [Слой 1: Замер]  MediaPipe Pose → метрики (JSON)
                              │
                              ▼
        [Слой 2: Интерпретация]  LLM-адаптер → структурированный разбор (JSON)
                              │
                              ▼
                      [Отчёт + захват лида]
```

### Слой 1 — Замер (детерминированный, бесплатный)
- **MediaPipe Tasks Vision → Pose Landmarker**, запуск в браузере (WASM/WebGL).
- 33 ключевые точки на каждый кадр. Используем 2D image-координаты (нормализованные) для сагиттальных углов.
- Всё, что можно посчитать формулами — считаем формулами, **без участия LLM**.

### Слой 2 — Интерпретация (модель-агностичная)
- Принимает только компактный JSON метрик (+ опционально 3–5 ключевых кадров).
- Отдаёт структурированный разбор (см. контракт ниже).
- **Адаптер за интерфейсом**, чтобы переключать провайдера без переписывания. Реализуй обоих:
  - `claude` (по умолчанию: `claude-opus-4-8`)
  - `openai` (`gpt-5.5`)
- Выбор модели — через env/конфиг. Цель — A/B качества разбора по факту.

## 4. Технологический стек

- **Frontend/route:** Next.js (как в репо), страница `app/tools/run-analysis/`.
- **Поза:** `@mediapipe/tasks-vision` (Pose Landmarker), модель `pose_landmarker_full` (баланс точность/скорость). Грузить лениво, только на странице тула.
- **LLM-вызов:** серверный route (`app/api/run-analysis/route.ts`), ключи **только на сервере**. Клиент шлёт JSON метрик, не видео.
- **ChatPlace:** интеграция через их API/вебхук (см. §9).

## 5. Пользовательский флоу (экран за экраном)

1. **Вход.** Юзер пришёл по ссылке из ChatPlace. Тёмный экран, обещание: «Разбор твоей техники бега за 60 секунд». Кнопка «Начать».
2. **Короткая форма.** Рост (см), вес (кг), обычный темп (мин/км), цель (выбор: «без травм» / «быстрее» / «техника»). Нужно для точности и персонализации. Все поля — мягко обязательные, но с дефолтами.
3. **Инструкция по съёмке** (критично для качества):
   - Снимать **строго сбоку**, горизонтально (landscape).
   - 5–10 секунд, всё тело в кадре, телефон неподвижен (попроси опору/штатив).
   - Ровный темп, минимум 3–4 полных шаговых цикла в кадре.
   - Показать схему-картинку правильного кадра.
4. **Загрузка готового видео** (выбор файла из галереи; запись в браузере НЕ делаем — для бега бесполезна). Принять mp4/mov, лимит ~30 МБ / 15 сек.
5. **Обработка (30–60 сек).** MediaPipe гонит позу по кадрам. Прогресс-индикатор. **Показать анимацию скелета поверх видео** — это «вау»-момент и шерится. Если позу не нашли / ракурс неверный — понятная ошибка + как переснять (см. §11).
6. **Отчёт** (см. §7).
7. **CTA + захват лида.** Мягкий призыв: «Хочешь, чтобы я разобрал лично / вступай в клуб». Форма контакта (или подтянуть из ChatPlace-контекста).

## 6. Слой замера — что именно считаем

Из side-view доступно и надёжно:

| Метрика | Как считаем | Надёжность |
|---|---|---|
| Угол колена (сгибание) | угол hip–knee–ankle в фазах контакта/маха | высокая |
| Наклон корпуса вперёд | угол линии плечо–таз к вертикали | высокая |
| Угол в тазобедренном | hip flexion/extension | средняя |
| Оверстрайд | положение стопы относительно проекции центра масс в момент контакта | средняя-высокая |
| Тип приземления | угол стопы/голеностопа в момент контакта (пятка/мид/носок) | средняя |
| Каденс (шаг/мин) | частота из периодичности вертикальных колебаний точек ног | высокая |
| Вертикальная осцилляция | амплитуда вертикального смещения таза | **относительная** (без калибровки — в условных, не в см) |
| Время контакта / полёта | по минимумам траектории стопы | **приблизительно** (зависит от fps) |

**Честные оговорки для реализации:**
- Метрики из 2D-видео с одной камеры — проекции. Вертикальную осцилляцию, GCT и flight time даём как **относительные/качественные**, не абсолютные в мм/мс, если нет калибровки и высокого fps.
- Фазы цикла (контакт → опора → отталкивание → мах) детектим по траектории стопы.
- Все пороги «норма/отклонение» вынеси в **конфиг** (`reference-ranges.ts`) — Игорь будет их тюнить. Не зашивай в код. Стартовые значения проставь как разумные плейсхолдеры с пометкой `// TODO: validate with Igor`.

## 7. Отчёт — структура

Тёмный бренд. Сверху вниз:

1. **Герой:** кадр(ы) с наложенным скелетом и подписанными ключевыми углами.
2. **Главные находки (2–3):** заголовком, с тяжестью (ок / обрати внимание / важно). Пример: «Оверстрайд — стопа приземляется заметно впереди центра масс».
3. **Детали:** таблица метрик против нормы (из конфига), визуально (бар/шкала).
4. **Рекомендации:** под каждую находку — что делать + 2–3 корректирующих упражнения.
5. **CTA-блок:** переход на личный разбор / клуб.
6. **Дисклеймер:** экспресс-скрин, не медицинский/лабораторный вывод.

## 8. Контракт слоя интерпретации (LLM)

### Вход (формирует сервер из метрик слоя 1)
```json
{
  "runner": { "height_cm": 178, "weight_kg": 72, "pace_min_km": 5.3, "goal": "technique" },
  "metrics": {
    "knee_angle_contact_deg": 142,
    "trunk_lean_deg": 6,
    "cadence_spm": 168,
    "foot_strike": "heel",
    "overstride_ratio": 0.18,
    "vertical_oscillation_rel": 0.42,
    "phases_detected": ["contact","midstance","toeoff","swing"]
  },
  "reference_ranges": { "...": "из конфига" }
}
```

### Выход (строго JSON, парсится сервером)
```json
{
  "headline_findings": [
    { "title": "...", "severity": "ok|attention|important", "explanation": "..." }
  ],
  "metrics_commentary": [ { "metric": "cadence", "verdict": "...", "note": "..." } ],
  "recommendations": [ { "issue": "...", "advice": "...", "drills": ["...","..."] } ],
  "summary": "1–2 абзаца голосом Игоря"
}
```

### Требования к промпту
- Язык — **русский**, тон — тренерский, тёплый, премиальный (голос Игоря).
- **Только** интерпретирует переданные числа. **Не выдумывает** углы/метрики, которых нет во входе.
- Если данных мало/качество низкое — честно говорит об ограничении, не фантазирует.
- Системный промпт требует вернуть **только JSON**, без преамбулы и markdown-обёрток. Сервер парсит безопасно (strip fences, try/catch).
- Адаптер один интерфейс, две реализации (`claude` / `openai`), выбор по env.

## 9. Захват лида / ChatPlace

Автоматизацию воронки (кодовое слово → выдача ссылки → дожим в директе) **настраивает Игорь на стороне ChatPlace**. Задача тула — минимальная стыковка:

- **Принять контекст** подписчика из ссылки ChatPlace (идентификатор через query-параметр).
- **Отдать событие «анализ завершён»** наружу: webhook/redirect с этим идентификатором (+ опц. ключевые находки), который Игорь заведёт в ChatPlace как триггер следующего шага.
- Если контекста нет (зашли напрямую) — простая форма контакта.
- ChatPlace — no-code платформа на официальном Meta Graph API; **точные возможности входящего вебхука/API уточнить на этапе интеграции** (часть может настраиваться внутри ChatPlace без кода). Любые токены — в env, на сервере.

## 10. Приватность и безопасность

- **Видео обрабатывается на клиенте** (MediaPipe в браузере). На сервер уходит **только JSON метрик**, не само видео. Это и приватность, и стоимость.
- Видео **не хранить** на сервере в v1. Если нужно превью кадров в отчёте — держать в памяти браузера/blob, не загружать в стор.
- **Ключи LLM и ChatPlace — только серверный route**, никогда в клиентский бандл.
- Никаких `.env`, ключей, кред в клиентском коде. Следуй секрет-менеджменту репозитория.

---

## 11. Краевые случаи и обработка ошибок

- Поза не найдена / в кадре нет человека → понятная ошибка + чек-лист пересъёмки.
- Неверный ракурс (не сбоку) → эвристика (напр. обе стороны тела налезают) → предупреждение «сними сбоку».
- Слишком короткое видео / мало шаговых циклов → попросить длиннее.
- Дрожащая камера → предупреждение о возможной неточности.
- LLM вернул невалидный JSON → ретрай один раз, затем мягкий фолбэк (показать метрики без нарратива).

## 12. Критерии приёмки (как Игорь тестит финал)

- [ ] Маршрут открывается на `/tools/run-analysis`, тёмный бренд, токены из репо.
- [ ] Полный флоу проходится на реальном видео сбоку: форма → инструкция → загрузка → обработка → отчёт.
- [ ] Скелет накладывается на видео, ключевые углы подписаны.
- [ ] Отчёт содержит 2–3 находки + детали + рекомендации + CTA + дисклеймер.
- [ ] Разбор на русском, голосом Игоря, без выдуманных чисел.
- [ ] Переключение модели `claude`↔`openai` работает через конфиг.
- [ ] Метрики на сервер уходят как JSON, видео не покидает браузер.
- [ ] Пороги норм лежат в конфиге, легко правятся.
- [ ] Корректные ошибки на «плохих» видео.
- [ ] Линт/типы/сборка зелёные, правила репо соблюдены.

## 13. Решения и открытые вопросы

**Решено:**
- Корректирующие упражнения → **плейсхолдеры**, Игорь добавит свои потом.
- Видео → **только загрузка готового файла**, запись в браузере не делаем.
- Лид-сервис → **ChatPlace** (автоматизацию настраивает Игорь, тул отдаёт событие наружу).

**Открыто (не блокирует старт):**
1. Стартовые пороги «норма/отклонение» по метрикам — задаст Игорь после первого прогона (стоят плейсхолдеры с `// TODO`).
2. Точная схема стыковки с ChatPlace (формат вебхука/redirect, что прокидывать) — уточнить на этапе интеграции.
