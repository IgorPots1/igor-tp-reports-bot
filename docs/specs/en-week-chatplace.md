# Бесплатная неделя @runnigor: как собрать автоматизацию в ChatPlace

Страница: `igorp.run/en/week` (английская), личный план: `igorp.run/en/week/p/<token>`.
Код: `src/features/en-week/*`, API: `src/app/api/en-week/*`. Всё за флагом `EN_WEEK_ENABLED`.
Автоматизацию в ChatPlace собирает Игорь (нужен Pro: действие **HTTP request**). Код ничего
в ChatPlace не создаёт и сам в директ не пишет: тексты отдаёт API, отправляет ChatPlace.

## 1. Доступ к API

- Базовый адрес: `https://igorp.run/api/en-week/`
- Заголовок в КАЖДОМ HTTP-запросе: `x-en-week-key: <значение EN_WEEK_API_KEY>` (сравнивается
  на сервере за постоянное время; без ключа или с неверным → 401).
- Флаг выключен → 404 `{ok:false, skipped:"EN_WEEK_ENABLED off"}`; страница показывает «Coming soon».
- `c`: id клиента ChatPlace, та же переменная, что уже стоит в ссылке разбора Стравы
  (`/breakdown?c=...&u={{username}}`).

| Метод | Путь | Что делает |
|---|---|---|
| GET | `today?c=<id>` | Что отправить сейчас. Главный вызов цикла. |
| POST | `checkin` body `{"c":"<id>","value":"easy\|ok\|hard\|skipped\|pain"}` | Отметка «как прошло», ответ для директа. |
| GET | `status?c=<id>` | Стадия для ветвлений (нет плана / идёт неделя / всё). |

### GET /today: поля ответа (замапить в переменные через JSONPath)

| Поле | Переменная (пример) | Смысл |
|---|---|---|
| `$.send` | `ew_send` | `true` → отправить сообщение сейчас. `false` → ничего не слать. |
| `$.message` | `ew_message` | Готовый текст на английском, до 900 символов. |
| `$.buttons` | `ew_buttons` | Какие кнопки ставить: `checkin`, `ack`, `offer`, `none`. |
| `$.url` | `ew_url` | Личная ссылка на план (или на анкету, если плана ещё нет). |
| `$.cta_url` | `ew_cta` | Ссылка «Message Igor» (WhatsApp через наш счётчик), есть только при `buttons=offer`. |
| `$.image_url` | `ew_image` | Фото к истории Марины (единственная история в английской версии) или пусто. Если не пусто: сначала картинка, потом `{{ew_message}}`. |
| `$.kind` | `ew_kind` | Тип: workout, checkin_ask, logged, rest, preview, before_start, summary, followup, final, no_plan, health_stop, quiet, done. |
| `$.stage` | `ew_stage` | no_plan, health_stop, before_start, week, post, done. |
| `$.has_workout_today` | | Есть ли сегодня тренировка. |

`/today` идемпотентен: первый вызов в нужном окне дня даёт `send:true` и помечает окно,
повторные вызовы в том же окне дают `send:false, repeat:true`. Для ручной проверки
добавить `&peek=1`: ответ тот же, окно не помечается.

### POST /checkin

Ответ `{ok, reply}`: `reply` отправить человеку сразу (кнопок не нужно, он только что нажал).
Отметка ложится на сегодняшнюю тренировку, а если сегодня её нет, на последнюю прошедшую
без отметки. Повторное нажатие той же кнопки ничего не задваивает.

## 2. Расписание и окно 24 часов

Instagram разрешает писать человеку 24 часа после ЕГО последнего сообщения (нажатие быстрой
кнопки считается). Поэтому каждое сообщение недели просит нажать кнопку, и между такими
сообщениями не больше 20 часов.

Время считает СЕРВЕР по часовому поясу человека (браузер отдаёт его при создании плана):
ChatPlace просто опрашивает `/today` каждые 2 часа, а сервер отвечает `send:true` только в
нужное окно по местному времени человека:

| Окно (местное) | Когда шлёт |
|---|---|
| утро 07:00-10:00 | день тренировки: задание (`buttons=checkin`) |
| день 12:00-15:00 | день отдыха / до старта: совет, история ученика или оффер (`ack` / `offer`) |
| вечер 18:00-21:00 | день тренировки: «как прошло?» (`checkin`) или «записал, дальше...»; день отдыха: что завтра (`ack`); день 7: итог (`offer`) |
| после недели | день 8 в 12-15: напоминание (`offer`), день 10 в 12-15: последнее (`offer`), дальше `stage=done` |

Худший разрыв при опросе раз в 2 часа: вечер 18:00 → следующий день до 14:00 = 20 часов.
`check:en-week` проверяет это на всех наборах дней и в четырёх часовых поясах.

Продающее (история Марины, оффер) не чаще одного в день, оффер не раньше второй отметки (или с
5-го дня), в 7-й день оффер в итоге. День 8: напоминание, день 10: последнее сообщение, оба без
истории. В английской версии только одна история, Марины (перевод русской, то же фото);
Аня, Надя и Саша не используются (решение Игоря 28.10.2026). Для всех стран одинаково.

## 3. Схема автоматизации (рекомендация)

**А. Вход (кодовое слово, например WEEK, в комментарии или в директ).**
1. Сообщение с быстрой кнопкой «Send me the link» (нажатие открывает окно 24 часа).
2. После нажатия: сообщение «Here's your free week: 4 quick questions, then your workouts.»
   + URL-кнопка «Get my free week» → `https://igorp.run/en/week?c={{client_id}}&u={{username}}`.
3. Пауза 3 часа → HTTP GET `status?c=...` → если `stage = no_plan`: сообщение-напоминание
   («Your free week is one minute away...» + та же URL-кнопка + быстрая кнопка «Got it»).
   Если по-прежнему `no_plan` через сутки, автоматизация заканчивается.
4. Если `stage` не `no_plan` и не `health_stop` → запустить автоматизацию Б (`run_automation`).

**Б. Цикл недели.**
1. HTTP GET `today?c=...` с маппингом полей из таблицы выше.
2. Условие `ew_send = true`:
   - нет → шаг 5;
   - да → ветка по `ew_buttons`:
     - `checkin`: сообщение `{{ew_message}}` + 5 быстрых кнопок **Easy / OK / Hard / Skipped /
       Something hurt** + URL-кнопка «My plan» → `{{ew_url}}`;
     - перед любой из веток: если `ew_image` не пустой, отдельное сообщение-картинка по ссылке `{{ew_image}}`;
     - `ack`: сообщение `{{ew_message}}` + быстрая кнопка **Got it** + URL-кнопка «My plan»;
     - `offer`: сообщение `{{ew_message}}` + URL-кнопка **Message Igor** → `{{ew_cta}}` +
       быстрая кнопка **Got it**;
     - `none`: сообщение `{{ew_message}}` без кнопок.
3. Каждая из 5 кнопок отметки ведёт в свой шаг: HTTP POST `checkin` с телом
   `{"c":"{{client_id}}","value":"easy"}` (`ok`, `hard`, `skipped`, `pain` соответственно),
   маппинг `$.reply` → `ew_reply`, затем сообщение `{{ew_reply}}`.
4. «Got it» ничего не вызывает (просто держит окно открытым), можно поставить реакцию.
5. Условие `ew_stage = done` → конец. Иначе пауза **2 часа** (delay тип 3, значение 2) и
   переход на шаг 1 (`change_step`).

Цикл живёт ~11 дней (≈130 вызовов на человека). Если в ChatPlace ограничено число повторов
цикла, запасной вариант: три фиксированных вызова в день по времени аккаунта (delay тип 7,
«завтра в HH:MM») с явным `&slot=morning|midday|evening`. Тогда окна считаются по времени
аккаунта, а не человека, и для лидов в далёких поясах утро придёт не утром: поэтому основной
вариант именно опрос раз в 2 часа.

**Быстрые кнопки отметки в любой момент.** Кнопки Easy/OK/.../Something hurt под утренним
сообщением можно нажать сразу после пробежки, не дожидаясь вечера: отметка ляжет на сегодня,
и вечером придёт «Logged, thank you...» вместо вопроса.

## 3а. Скриншоты тренировок

Вечерний вопрос «How did today's workout go?» теперь заканчивается строкой: скриншот с часов или
из приложения (Garmin, Strava, Apple Fitness) можно добавить к тренировке на странице плана,
кнопка «My plan». Файлы в ChatPlace не принимаем: ChatPlace не умеет передать их к нам, поэтому
загрузка только на странице. До 3 скриншотов на тренировку, только картинки, приватное
хранилище, ссылки подписанные. Уведомлений тренеру о загрузках нет.

## 3б. Анкета на странице

Ветвление по цели, как в приложении «AI running coach»: Start running (сейчас бегаешь? сколько
без остановки?), Come back to running (когда последний раз регулярно? что мог тогда?), Run
regularly, Train for a race (дистанция, месяц, результат за 12 месяцев). Дальше дни (Start 2-3,
Race 3-4, остальные 2-4), конкретные дни, базовый уровень (км в неделю, самая длинная, опыт
интервалов) и экран здоровья. ChatPlace ничего из этого не касается.

## 4. Проверка вручную

```bash
curl -s -H "x-en-week-key: $EN_WEEK_API_KEY" "https://igorp.run/api/en-week/status?c=<id>"
curl -s -H "x-en-week-key: $EN_WEEK_API_KEY" "https://igorp.run/api/en-week/today?c=<id>&peek=1"
curl -s -H "x-en-week-key: $EN_WEEK_API_KEY" "https://igorp.run/api/en-week/today?c=<id>&slot=evening&peek=1"
curl -s -X POST -H "x-en-week-key: $EN_WEEK_API_KEY" -H "Content-Type: application/json" \
  -d '{"c":"<id>","value":"ok"}' https://igorp.run/api/en-week/checkin
```

Полный прогон четырёх персонажей (экраны страницы и все сообщения по дням):
`npm run en-week:simulate -- /tmp/en-week-sim.md`.

## 5. Что где видно

- Тренеру в Telegram (основной бот, первый id из `TELEGRAM_COACH_CHAT_IDS`, как у русской
  пробной недели) приходит ОДНО сообщение, когда человек создал план: ник, цель, сколько бежит,
  дни, страна, тип плана. Больше никаких уведомлений (ни на «Something hurt», ни на отметки).

- Воронка: `en_week_events` (open → plan_created / health_stop → checkin → dm:* → offer_shown →
  cta_click), по людям `en_week_users` (`offer_dm_at`, `summary_dm_at`, `cta_clicked_at`...).
- Клики «Message Igor» также в `/admin/tools-stats` как инструмент `en-week` («EN: free training week»).
- Здоровье: хранится только `health_flag` (да/нет), что именно отмечено, не пишется никуда.
